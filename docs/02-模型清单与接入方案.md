# 模型清单与接入方案

> 目标：给用户「可选模型」的能力，同时保证成本可控、私域数据不违规外泄。
> 版本 v1.0

---

## 零、先说一个必须点破的幻觉

**"开源免费" ≠ "运行免费"。**

开源模型免的是**许可费**，算力费一分不少：

| 规模 | 显存需求 | 云 GPU 成本 | 折算 |
|---|---|---|---|
| 7B（4bit 量化） | 约 6–8 GB | ¥2–4 / 小时 | 包月 ¥1500–3000 |
| 14B | 约 12–16 GB | ¥4–8 / 小时 | 包月 ¥3000–5500 |
| 32B | 约 24 GB | ¥8–15 / 小时 | 包月 ¥5500–10000 |
| 70B | 需多卡 | ¥20+ / 小时 | 包月 ¥15000+ |

对比云端 API：100 万 token 大约 **¥1–10**。

**结论：日活低于 1000 时，自部署一定比调 API 贵得多。**

那什么时候该自部署？只有两种情况：

1. **数据不能出门**（私域资料、企业保密）——这正是你的核心需求
2. 日均 token 消耗极大（比如超过 10 亿/天），边际成本才追平

所以你的架构应该是 **混合的**：

```
私域敏感内容 → Windows 端本地模型（Ollama）→ 数据不出本机
普通问答     → 云端 API（便宜、能力强、无需显卡）
```

这既解决了"防泄密"，又不用为普通问答烧 GPU 钱。

## 四、页面上怎么让用户选（关键设计）

**不要给用户罗列 40 个模型名**——他不知道区别，只会选择困难。

### 按"三档"呈现，而不是按厂商

```
┌─ 选择模型 ───────────────────────────────────┐
│                                              │
│  ○ 本地模型          免费 · 数据不出本机      │
│    Qwen 7B（已安装）     ▸ 能力 ★★☆  速度 ★★★ │
│    Llama 8B（未安装）    ▸ 点击下载           │
│                                              │
│  ● 云端 · 快速便宜     ¥ · 数据在国内         │
│    GLM-4-Flash（免费）   ▸ 能力 ★★★  速度 ★★★ │
│    DeepSeek Chat         ▸ 能力 ★★★★ 速度 ★★  │
│                                              │
│  ○ 云端 · 旗舰        ¥¥¥ · 数据在海外        │
│    Claude Sonnet         ▸ 能力 ★★★★★ 速度 ★★ │
│    GPT 系列              ▸ 能力 ★★★★★ 速度 ★★ │
│                                              │
└──────────────────────────────────────────────┘
```

### 每张卡片必须显示的 5 个信息

| 字段 | 为什么必须显示 |
|---|---|
| 能力等级 | 用户要判断"够不够用" |
| 成本等级（¥/¥¥/¥¥¥） | 直接关系他的配额消耗速度 |
| **数据去向**（本地 / 国内 / 海外） | **合规底线，不能隐藏** |
| 是否开源 | 技术用户关心 |
| 上下文长度 | 长文档场景的关键 |

### 用户真正选的不是"模型"，是三个策略

1. **默认用哪个模型**
2. **是否允许使用海外模型**（默认关）
3. **私域资料是否强制只用本地模型**（默认开）

第 3 条是你"防泄密"承诺的技术兑现点。默认开启，用户关闭时要有明确警告。

## 五、代码怎么落地

### 数据表

```
model_providers          供应商（deepseek / qwen / ollama ...）
  └─ models              具体型号（code、能力、成本等级、数据去向）
user_model_preferences   每个用户的默认模型与策略
usage_records            每次调用的用量与成本（已有）
```

**模型目录存数据库，不硬编码在前端。** 理由：

- 新模型上线只需插一行数据，不用发版
- 不同用户等级可以只看到部分模型
- 价格调整、下线模型，后台改一条记录即可

### 网关（AGENTS.md 强制）

所有模型调用必须经过 `internal/modelgw`：

```
业务代码 → modelgw.Chat(ctx, req)
             ├─ 选 provider（按 model.code）
             ├─ 注入密钥（只在服务端）
             ├─ 超时 / 重试 / 降级
             ├─ 写 usage_records
             └─ 返回统一结构
```

**禁止业务代码直接调某家厂商的 SDK。** 否则你换模型、控成本、做灰度时，要改遍全项目。

### 安全规则

1. **密钥只在服务端**，前端只拿到 `modelId`
2. 前端提交的 `modelId` 必须校验「该用户有权使用该模型」
3. 私域内容调用前，检查目标模型的 `data_residency`，不满足就拒绝
4. 每次调用写 `usage_records`（含 model、tokens、cost_cents）

## 六、我给你推荐的起步组合

| 场景 | 用什么 | 理由 |
|---|---|---|
| 开发调试 | **Ollama + Qwen 7B** | 零成本、离线可用 |
| 普通问答 | **GLM 免费型号** 或 **DeepSeek** | 便宜到几乎免费 |
| 私域检索回答 | **Ollama 本地模型** | 数据不出机 |
| 高质量回答（付费用户） | **Claude / GPT** | 只在用户显式开启海外时可用 |
| 语音识别 | 云端 ASR（便宜）或本地 **FunASR** | 中文优先选 FunASR |
| 语音合成 | 云端 TTS 或本地 **CosyVoice** | 需音色克隆选 CosyVoice |
| 向量化 | **BGE-M3** | 中文检索效果最好的开源选择 |

**总成本估算（日活 100 人、每人 20 轮对话）**：约 ¥50–200/月。这个量级下不需要任何自建 GPU。
