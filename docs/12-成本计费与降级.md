# 成本计费与降级

> 版本 v1.0 ｜ 2026-11-19 ｜ 单价只写入口与口径，具体价格见系统设置里的「Token 价格」

## 0. 一句话结论

**本机模型零成本；云端模型按 token 计价，每次调用落一条 `usage_records`；当前是「记录成本」，还不是「扣费」。**

## 1. 成本口径

### 1.1 单位

- 单价：**分 / 百万 token**（整数，禁止浮点）
- 用量：token 数（整数）
- 成本：**分**（向下取整）

### 1.2 计算公式（与代码一致）

```
cost_cents = floor((prompt_tokens × 输入单价 + completion_tokens × 输出单价) / 1_000_000)
```

代码位置：

- 非流式：`src/kaixin_local_go/modelgw.go`（`cost :=` 一行）
- 流式：`src/kaixin_local_go/modelgw_stream.go`（同一公式，结束时随 `done` 下发）

### 1.3 单价来源

| 场景 | 存储位置 | 配置入口 |
|---|---|---|
| 本机客户端 | 本地库设置 `model.inputPriceCents` / `model.outputPriceCents` | 系统设置 → 模型接入 → 输入价/输出价 |
| 云端管理 | 服务端 `model_prices` 表（按模型一行） | 管理后台 → 充值与价格 |

本机 Ollama 模型单价留 0，成本自然为 0；此时结果里会带一句「未配置单价，费用按 0 计」。

## 2. 用量记录

每次模型调用写一条（本地 SQLite，迁移 `0005_usage.sql`）：

| 字段 | 含义 |
|---|---|
| `model` | 实际使用的模型名 |
| `prompt_tokens` | 输入 token |
| `completion_tokens` | 输出 token |
| `cost_cents` | 本次成本（分） |
| `elapsed_ms` | 耗时 |
| `created_at` | UTC 时间 |

界面上回显在回答下方：`模型 qwen2.5:3b · 输入 33 / 输出 21 tokens · 耗时 49.7s · 费用 ¥0`。

### 2.1 模型不返回用量时

部分 OpenAI 兼容服务在流式下不给 `usage`。此时按字符粗估（中文约 2 字符 ≈ 1 token），并在 `done` 里标 `estimated: true`，界面提示「token 为估算值」。

**估算值只用于显示，不参与任何结算**，避免用估算数字做账。

## 3. 三档方案

| 档位 | 典型选择 | 单次成本量级 | 适用 |
|---|---|---|---|
| **本机** | Ollama qwen2.5:3b | 0（只耗电） | 离线、隐私、试跑 |
| **经济云** | DeepSeek、通义 qwen-plus | 千 token 约 1–3 分 | 日常问答、生成方案 |
| **旗舰云** | 各家旗舰模型 | 千 token 约 10–60 分 | 复杂推理、长文 |

选择权在用户：同一套代码，改「模型接入」里的地址与模型名即可切换，不改代码。

## 4. 成本测算模板

按「人均日调用次数 × 平均 token」估月成本：

| 变量 | 取值 | 说明 |
|---|---|---|
| 日活用户 | U | 实际使用人数 |
| 人均日调用 | N | 问答 + 生成方案次数 |
| 平均输入 token | Pi | 含上下文，注意会随轮数增长 |
| 平均输出 token | Po | 一般远小于输入 |
| 输入单价 | Ci（分/百万） | 见第 1.3 节 |
| 输出单价 | Co（分/百万） | 同上 |

```
月成本（分） = U × N × 30 × (Pi × Ci + Po × Co) / 1_000_000
```

示例：100 人 × 每人每天 20 次 × 输入 2000 / 输出 500 token，
用「输入 1 分 / 输出 3 分（每百万）」这一档：

```
100 × 20 × 30 × (2000×1 + 500×3) / 1e6 = 60000 × 3500 / 1e6 = 210 分 ≈ 2.1 元/月
```

**便宜的根源是 token 小**：一旦把整段历史全量重发，Pi 会翻十倍，成本同比例上涨——这就是下文「上下文成本」要管的原因。

## 5. 计费正确性检查清单

- [ ] 金额一律整数分，不出现浮点
- [ ] 除以 1_000_000 时走整数除法（向下取整）
- [ ] 单价为 0 时明确提示「按 0 计」，不冒充有价
- [ ] 估算值有标记，不被当成真实用量
- [ ] 每次调用都能在 `usage_records` 里查到
- [ ] 换模型后单价跟着换（不能沿用上一个模型的价）

## 6. 降级策略

### 6.1 已实现

| 场景 | 行为 |
|---|---|
| 模型未配置 | 接口返回明确提示，引导去「系统设置 → 模型接入」 |
| 本机模型不可用 | `/api/generate/*` 返回 502，前端回退内置模板，功能不瘫 |
| 流式连接失败 | 下发 `error` 事件，界面显示原因，不会静默卡住 |
| 模型返回非 JSON | 生成类接口判定失败 → 前端用模板兜底 |
| 超长上下文 | 后端滑动窗口裁剪（6000 字符预算）+ 前端超 14 条自动摘要 |
| 单价未配置 | 成本按 0 计并注明，不伪造金额 |

### 6.2 未实现（记着，别当成已有）

| 缺口 | 影响 |
|---|---|
| 多供应商自动切换 | 主供应商挂了要人工改配置 |
| 限流与配额 | 单用户狂刷会把额度打光 |
| 余额扣减 | 用户余额字段有了，但计费不扣余额（只记录） |
| 成本阈值告警 | 超预算不会自动提醒 |
| 缓存命中 | 相同问题重复计费 |

## 7. 已知风险

1. **本机 3B 模型慢**：首字 40–60 秒，成本为 0 但体验差；实际使用建议云端。
2. **上下文膨胀**：多轮对话若不裁剪，输入 token 线性增长，成本同步增长。
3. **估算不精确**：字符估算对英文偏差较大，仅作显示参考。
4. **单价手工维护**：改了官网价格不会自动同步，需要人工更新设置。
