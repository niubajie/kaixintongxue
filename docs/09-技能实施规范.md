> **状态：相关功能已于 2026-11-20 下线，本文档仅作历史留档。**
>
> 版本 v1.1 ｜ 用途：让 AI 编程工具按统一结构实现新技能，而不是每次重新发明。
>

## 1. 能力原语总表

**所有技能都由 6 个原语组合而成。不允许发明第 7 个。**

| 原语 | 覆盖需求 | 实现位置 | 详见 |
|---|---|---|---|
| **Auth** 授权 | ①网站注册登录 ②网站授权 | Go 服务 + 系统浏览器/WebView | 第 2 节 |
| **Browser** 页面自动化 | ③发布视频/商品 | Go sidecar + Playwright | 第 3 节 |
| **AppCall** 本地软件 | ④调用剪映等软件 | Go sidecar + 文件/草稿交换 | 第 4 节 |
| **Render** 报表 | ⑤图形化报表 | 前端 ECharts | 第 5 节 |
| **Install** 部署 | ⑥软件安装 | 见 `docs/07` | 第 6 节 |
| **Store** 存储 | ⑦数据存储 | PG / SQLite | 第 7 节 |

**判断规则**：一个技能要"登录别人系统"就是 Auth，"操作网页"就是 Browser，"驱动本地软件"就是 AppCall，以此类推。

## 2. 原语一：Auth（注册与登录、授权）

### 2.1 只做授权，不做代注册

| 需求 | 正确做法 | 禁止 |
|---|---|---|
| 让用户用抖音账号 | **OAuth 2.0 授权码流程**，用户自己登录 | ❌ 代用户注册账号 |
| 拿到接口调用权 | 应用凭证 + 用户授权码换 token | ❌ 共享他人 token |
| 多账号管理 | 每个账号独立授权、独立存储 | ❌ 批量注册养号 |

> 批量注册/养号违反平台规则，且涉嫌非法经营。**这条没有技术变通空间。**

### 2.2 两种授权形态

| 形态 | 适用 | 优点 | 缺点 |
|---|---|---|---|
| **系统浏览器 + 本地回调** | 首选 | 兼容性最好，平台风控友好 | 需要起本地回调端口 |
| **内嵌 WebView** | 桌面端体验好 | 不跳出应用 | 部分平台禁止内嵌，可能被判风险 |

**默认用系统浏览器**。内嵌只在你确认平台允许时使用。

### 2.3 接口定义（Go 侧）

```go
type AuthProvider string // "douyin-open" | "douyin-shop" | ...

type AuthService interface {
    // 生成授权 URL（含 state 防 CSRF）
    BeginAuth(ctx context.Context, userID int64, provider AuthProvider) (authURL string, state string, err error)
    // 处理回调：校验 state → 换 token → 加密入库
    CompleteAuth(ctx context.Context, userID int64, provider AuthProvider, code, state string) (*Credential, error)
    // 取可用凭证（自动刷新，过期返回 ErrNeedReauth）
    GetCredential(ctx context.Context, userID int64, provider AuthProvider) (*Credential, error)
    // 撤销授权
    Revoke(ctx context.Context, userID int64, provider AuthProvider) error
}
```

### 2.4 Token 存哪

| 层 | 存什么 | 加密 |
|---|---|---|
| 客户端本地 | 用户自己的授权凭证 | **系统凭据管理器**（Windows Credential Manager） |
| 服务器 | 应用级 token、刷新令牌 | 数据库列级加密（AES-GCM）+ 密钥在 KMS |

**禁止把 access_token 写进日志、写进前端 localStorage、写进 Git。**

### 2.5 状态机

```
未授权 → 授权中 → 已授权 → 已过期 → 需重新授权
                    ↓
                  已撤销
```

**界面必须能显示"已过期，请重新授权"，而不是静默失败。**

## 3. 原语二：Browser（页面自动化）

### 3.1 优先级铁律

```
官方 API  >  开放平台接口  >  页面自动化
```

**能用接口就不动页面。** 页面自动化是最后手段。

| 需求 | 首选 | 页面自动化何时才用 |
|---|---|---|
| 发布视频 | 抖音开放平台 `video.create` | API 未开通该类目权限时 |
| 发布商品 | 抖店开放平台商品接口 | 同上 |
| 拉销量数据 | 抖店数据接口 | 后台独有、接口不提供时 |

### 3.2 页面自动化的四条硬约束

| 约束 | 原因 |
|---|---|
| **必须有头（可见窗口）** | 用户要看见在做什么；无头批量 = 自动化滥用特征 |
| **每一步用户确认** | 发布前必须让用户点"确认发布" |
| **不绕过验证码** | 遇验证码就停下，让用户手动过 |
| **单账号串行** | 不做多账号并发，那是养号行为 |

### 3.3 技术实现

```
Go sidecar
  └─ Playwright（独立进程，通过 CDP 通信）
       ├─ 用户数据目录持久化（保持登录态）
       ├─ 选择器策略：语义定位优先 → CSS 多候选 → 文本匹配
       └─ 每步截图存档，失败时附截图
```

**选择器必须多候选**，因为平台改版很频繁：

```jsonc
{
  "target": "发布按钮",
  "candidates": [
    { "by": "role", "value": "button", "name": "发布" },
    { "by": "text", "value": "发布" },
    { "by": "css", "value": "[data-e2e='publish-btn']" }
  ],
  "timeoutMs": 8000,
  "fallback": "manual"
}
```

全部失败 → 降级为"手动模式"，弹窗提示用户自己点。

### 3.4 禁止清单

| 禁止 | 原因 |
|---|---|
| 无头模式批量操作 | 平台风控直接判死 |
| 破解/绕过验证码 | 违法违规 |
| 多账号轮换 | 养号特征 |
| 自动关注/点赞/评论 | 明确违规 |
| 把账号密码存在本地 | 应该用授权，不该存密码 |

---

### 3.5 自动化分级（不是一律禁止）

页面操作分三级，**默认只做 A0**，确有必要才升到 A1：

| 级别 | 程序做到哪一步 | 例 |
|---|---|---|
| A0 仅直达 | 打开页面，用户操作 | 登录、支付、下单 |
| A1 辅助自动化 | 完成操作，最后一步人点 | 发布视频、上传商品 |
| A2 全自动读取 | 自动翻页采集 | 读列表数据 |

A1/A2 的三条硬约束：有头窗口、对外动作人工确认、失败即降级转人工。
判定细则见 `docs/10` 第 4.1 节。

## 4. 原语三：AppCall（本地软件调用）

### 4.1 三种调用方式，按侵入性从低到高

| 方式 | 侵入性 | 稳定性 | 适用 |
|---|---|---|---|
| **① CLI 参数** | 无 | 高 | 软件有命令行（ffmpeg、ollama） |
| **② 文件交换** | 无 | 高 | 输入输出都是文件 |
| **③ 工程文件注入** | 低 | 中 | 软件有可读的工程格式（剪映草稿） |
| **④ UI 自动化** | 高 | 低 | ❌ 不推荐 |

**优先 ①②③，避免 ④。**

### 4.2 剪映的正确做法：生成草稿，不遥控界面

剪映没有公开 API，但有本地草稿工程：

```
%LOCALAPPDATA%\JianyingPro\User Data\Projects\com.lveditor.draft\<项目名>\
├── draft_content.json     ← 轨道、素材、特效都在这里
├── draft_meta_info.json
└── materials/
```

**做法**：

```
1. 你的程序生成一个合法的草稿目录（含 draft_content.json）
2. 提示用户「已生成草稿，请在剪映中打开」
3. 用户打开剪映 → 看到项目 → 微调 → 自己导出
```

| 优点 | 缺点 |
|---|---|
| 不碰剪映界面，不会崩 | **草稿格式随版本变化** |
| 用户保留完全控制权 | 新版可能加密/校验，需适配 |
| 合规风险最低 | 需要做版本探测 + 降级 |

> **必须先做 1–2 天的技术验证（spike）**：用当前剪映版本生成一个最小草稿，确认能被正确打开。这个格式没有官方文档，只能试。

### 4.3 降级策略

| 情况 | 降级动作 |
|---|---|
| 草稿格式不兼容 | 改为「导出素材 + 分镜清单」，用户手动在剪映里拼 |
| 软件未安装 | 提示安装，或改用 ffmpeg 自建剪辑 |
| 版本过新/过旧 | 记录版本号，提示"未适配该版本" |

### 4.4 禁止清单

| 禁止 | 原因 |
|---|---|
| 模拟鼠标键盘驱动商业软件 | 极不稳定，且可能违反软件许可 |
| 注入 DLL / Hook 进程 | 安全软件直接拦截，法律风险 |
| 静默替用户导出上传 | 用户失去控制权 |

## 5. 原语四：Render（报表）

### 5.1 技术选型

| 项 | 选择 |
|---|---|
| 图表库 | **ECharts**（中文生态最好，图表类型最全） |
| 渲染位置 | **前端**（交互、缩放、导出都方便） |
| 数据来源 | 后端聚合好的结果，**前端不做聚合计算** |
| 导出 | ECharts `getDataURL()` → PNG；PDF 用打印样式 |

### 5.2 图表选择表

| 数据形态 | 图表 |
|---|---|
| 时间序列（日/周销量） | 折线图 |
| 分类对比（Top 10 商品） | 横向条形图 |
| 占比（品类分布） | 饼图 / 环形图 |
| 双指标（销量 + 播放量） | 双 Y 轴折线 |
| 转化漏斗（曝光→点击→下单） | 漏斗图 |
| 关联（价格 vs 销量） | 散点图 |

### 5.3 数据契约

```ts
interface ChartPayload {
  title: string;
  type: "line" | "bar" | "pie" | "funnel" | "scatter";
  dimensions: string[];          // X 轴 / 分类
  series: { name: string; data: number[] }[];
  unit?: string;                 // "件" / "%" / "元"
  updatedAt: string;             // ISO 8601
}
```

**后端返回这个结构，前端直接渲染。** 不要前端拼 SQL，也不要前端算同比环比。

### 5.4 禁止

| 禁止 | 原因 |
|---|---|
| 前端聚合百万行 | 卡死浏览器 |
| 每张图单独请求 | 请求风暴 |
| 报表数据不落库、每次现算 | 慢且不可追溯 |

## 6. 原语五：Install（软件部署）

详见 [`docs/07`](07-技能部署功能方案.md) 第 4、5 节。要点复述：


**先过许可证，再谈体积。**

## 7. 原语六：Store（数据存储）

详见 [`docs/08`](08-数据库设计与管理.md)。这里只补充**业务数据归属**：

| 数据 | 存哪 | 理由 |
|---|---|---|
| 账号、授权凭证 | 服务器 PG（加密列） | 换设备要能用 |
| 商品销量历史 | 服务器 PG | 需要跨设备、跨时间对比 |
| 抓取的原始页面 | 对象存储 | 体积大，可追溯 |
| 生成的视频/图片 | 对象存储 | 同上 |
| 用户私域文档 | **本地 SQLite** | 不出本机 |
| 任务队列与状态 | Redis | 短生命周期 |
| 操作日志 | 服务器 PG（`audit_logs`） | 合规与排障 |

**判断规则**：需要跨设备、需要审计 → 服务器；涉及用户隐私资产 → 本地。

## 8. 技能包规范（统一结构）

每个技能是一个目录，AI 按这个结构实现，不允许自创：

```
skills/<skill-id>/
├── manifest.json    技能元数据（必需）
├── schema.json      输入参数 JSON Schema（必需）
├── prompt.md        给 LLM 的技能说明（可选，AI 调用时需要）
└── ui/              专属界面（可选）
```

### 8.1 manifest.json

```jsonc
{
  "id": "douyin-product-sales",
  "version": "1.0.0",
  "name": "抖音商品销量采集",
  "primitives": ["auth", "browser", "store"],
  "requires": {
    "auth": ["douyin-shop"],
    "software": [],
    "models": []
  },
  "steps": [
    { "id": "auth",    "primitive": "auth",    "action": "ensure",  "args": { "provider": "douyin-shop" } },
    { "id": "fetch",   "primitive": "browser", "action": "call",    "args": { "endpoint": "/api/goods/stats" } },
    { "id": "persist", "primitive": "store",   "action": "upsert",  "args": { "table": "product_stats" } }
  ],
  "verify": ["返回行数 > 0", "关键字段非空"]
}
```

### 8.2 三条规范

| 规范 | 说明 |
|---|---|
| `primitives` 只能取第 1 节的 6 个值 | 新增原语必须先改本文档 |
| `steps` 是一个线性序列 | 不做复杂 DAG，够用 |
| `verify` 必须有 | 没有验收条件的技能不允许上线 |

## 9. 新技能接入流程（AI 按此执行）

```
[1] 判定原语        查第 1 节表，列出这个技能用到哪几个原语
[2] 写 manifest     填 id / primitives / requires / steps / verify
[3] 定义 schema     输入参数 JSON Schema，字段写清楚类型与必填
[4] 实现步骤        每个 step 落到具体函数，禁止跨层
[5] 写验收用例      至少 1 条成功路径 + 2 条失败路径
[6] 前端界面        用现有组件，不新造轮子
[7] 合规检查        过第 10 节清单
[8] 提交            一个技能一个提交
```

**第 7 步不通过，前面全白做。**

## 10. 上线前验收清单

| # | 检查项 | 不通过会怎样 |
|---|---|---|
| 1 | 是否优先使用官方 API | 用 RPA 顶替会封号 |
| 2 | 授权是否走 OAuth，未存密码 | 违规且不安全 |
| 3 | 发布类动作是否有人工确认 | 用户失去控制权 |
| 4 | 是否有降级路径（人工兜底） | 平台一改版全线崩 |
| 5 | Token 是否加密存储、日志是否脱敏 | 泄露事故 |
| 6 | 是否有 `verify` 条件 | 失败了也不知道 |
| 7 | 是否有失败截图/日志 | 无法排障 |
| 8 | 数据归属是否符合第 7 节 | 隐私或合规问题 |
| 9 | 许可证是否核对（内置软件） | 法律风险 |

## 12. 指导性文案

> **一、能用接口的，绝不模拟点击。**
> 官方 API 是第一选择，页面自动化是最后手段。每多用一次模拟点击，就多一分封号风险。
>
> **二、需要授权的，用户必须在场。**
> 我们不替用户注册账号、不替他保管密码、不替他点"同意"。授权这件事，只能用户自己完成。
>
> **三、能生成工程文件的，绝不遥控软件界面。**
> 给剪映一份草稿，比操控剪映的鼠标可靠一百倍。**合作式自动化，永远优于控制式自动化。**
>
> **四、任何对外发布的动作，必须有一次明确的人工确认。**
> 发视频、发商品、发评论——机器可以准备好一切，但最后那一下必须是人点的。
>
> **五、每个技能都是"原语 + 参数"的组合。**
> 不允许发明新原语，不允许绕过验收清单，不允许没有降级路径。
>
> **六、先过许可证，再谈体积；先过合规，再谈功能。**
> 顺序错了，做得越多，返工越大。

## 13. 一页速查

| 你要做的事 | 用哪个原语 | 一句话规则 |
|---|---|---|
| 让用户登录抖音 | Auth | OAuth，不代注册 |
| 拿授权后的接口数据 | Auth + Browser | 先查有没有 API |
| 自动发视频/商品 | Browser | 优先 API，RPA 要用户在场 |
| 调剪映剪辑 | AppCall | 生成草稿，不遥控界面 |
| 做数据看板 | Render | 后端聚合，前端画图 |
| 装 ffmpeg / Ollama | Install | 内置 / 按需 / 引导 |
| 决定数据放哪 | Store | 跨设备上云，隐私留本地 |
