# 权限矩阵草案（SYS-02）

> 状态：**已定稿**（2026-11-18）。第 6 节的五个决策点已按建议确认，见 6.6。
> 对应需求：FR-SYS-02「六类资源乘以三种角色的读写规则在服务层强制校验；
> 越权请求返回拒绝并记审计；前端隐藏不作为唯一手段」。

---

## 1. 先说清楚一个前提

需求写的「六类资源 × 三种角色在服务层强制校验」，但我们的架构里
**六类资源有四个半在本机**，服务端根本看不到：

| 编号 | 资源域 | 现在存在哪 | 服务端能强制吗 |
|---|---|---|---|
| R1 | 问答与技能运行（会话、部署任务） | 本机 SQLite + 内存 | 只能管云端那部分 |
| R2 | 目标与任务数据 | 本机 localStorage | 否（除非做云同步） |
| R3 | 本地资料文档与知识库 | 本机磁盘 + SQLite | 否，且受「私域不上传」红线约束 |
| R4 | 成员与权限管理 | 服务端 PostgreSQL/SQLite | **能** |
| R5 | 软件安装与系统设置 | 目录在服务端、安装在本地 | 一半 |
| R6 | 数据库备份与恢复 | 服务端 | **能** |

所以这份草案分两层：

- **服务端强制层**：R4、R6 全部，R5 的目录部分。这是真正能"越权返回拒绝并记审计"的部分。
- **本机规则层**：R1/R2/R3 在本机按 `user_id` 隔离；单机一个用户时等同于"本人+本人"，
  多成员共享一台电脑时才需要额外的本机账号切换（当前没有）。

**这是一条需要你拍板的事**（见 6.1）：服务端强制的范围，是否就限定在 R4/R5/R6。

---

## 2. 角色定义

| 角色 | 内部值 | 数量 | 说明 |
|---|---|---|---|
| 拥有者 | `Owner` | 唯一 | 部署时创建的第一个账号，不可被删除或降级 |
| 管理员 | `Admin` | 0..N | 由 Owner 指派；可管理成员与目录 |
| 成员 | `Member` | 0..N | 默认角色；只能操作自己的数据 |

当前服务端已有这三个值（`admin_users.go` 里做校验），缺的是**逐资源的规则**。

---

## 3. 权限矩阵（草案）

记法：`读` = 查看 / `写` = 新增与修改 / `删` = 删除 / `管` = 分配给他人的权限。

### 3.1 服务端强制（一定要做）

| 资源 | 操作 | Owner | Admin | Member |
|---|---|---|---|---|
| **R4 成员** | 读列表 | ✅ 全部 | ✅ 全部 | ⚠️ 仅本人 |
| | 写（改角色/启停） | ✅ 任何人 | ✅ 仅 Member | ❌ |
| | 删 | ✅ 任何人 | ✅ 仅 Member | ❌ |
| | 管（指派 Admin） | ✅ | ❌ | ❌ |
| **R4 审计** | 读 | ✅ | ✅ | ❌ |
| **R5 软件目录** | 读 | ✅ | ✅ | ✅ |
| | 写/删 | ✅ | ✅ | ❌ |
| **R6 备份** | 触发备份 | ✅ | ✅ | ❌ |
| | 恢复 | ✅ | ❌ | ❌ |
| | 下载备份 | ✅ | ❌ | ❌ |

要点：

- **Admin 不能动 Admin 和 Owner**，只能管 Member。防"两个管理员互相踢"。
- **恢复与下载备份只给 Owner**：这两件事能把整库回滚或带离服务器。
- 删除自己：任何角色都不能删自己（避免把唯一拥有者删没了）。

### 3.2 本机规则（本机执行，服务端无法强制）

| 资源 | Owner | Admin | Member |
|---|---|---|---|
| R1 会话与部署任务 | 本人读写 | 本人读写 | 本人读写 |
| R2 目标 / 学习 / 应用笔记 | 本人读写 | 本人读写 | 本人读写 |
| R3 本地资料与知识库 | 本人读写 | 本人读写 | 本人读写 |
| R5 本机安装与系统设置 | 可改 | 可改 | **可改**（本机是自己的电脑） |

单机场景下这些规则退化为"只能看到自己的数据"，靠 `user_id` 过滤即可，
与现有红线（每个查询带 `user_id`）一致。

## 4. 怎么落地（服务端）

### 4.1 中间件做粗筛，handler 做细判

```
请求 → 认证中间件（有会话？） → 资源中间件（角色够不够进这个路由？） → handler（这条数据是不是他的？）
```

三层缺一不可：

- **认证**：没有会话直接 401；
- **路由级**：把 `/api/admin/*` 整体限定为 Owner/Admin；
- **数据级**：成员只能改自己的行，靠 SQL 条件 `WHERE user_id = $1`。

只做路由级不够——同一路由里，Admin 能改 Member 但改不了别人 Admin，这是数据级判断。

### 4.2 越权要留痕

每次拒绝写一条 `audit`：

| 字段 | 内容 |
|---|---|
| 时间 | UTC |
| 账号 | 请求者 |
| 动作 | `deny:admin.users.update` |
| 对象 | 目标用户 id |
| 原因 | `role_member_cannot_manage_admin` |
| 来源 IP / UA | 保留，便于排查（**不记密码、不记 token**） |

### 4.3 统一拒绝响应

```json
{ "code": 10004, "message": "没有权限执行该操作", "data": null, "traceId": "..." }
```

HTTP 403。前端按 `code` 提示，不靠文案匹配。

### 4.4 前端只做体验

前端按能力隐藏按钮，但**服务端必须再判一次**。现有 `requireAdmin` 保留，
新增 `requireRole(roles...)` 与 `requireSelfOrAdmin(userID)` 两个更细的检查。

## 6. 需要你确认的决策点

### 6.1 服务端强制范围

**问题**：R1/R2/R3 都是本机数据，服务端强制不了。

| 选项 | 含义 | 代价 |
|---|---|---|
| A（建议） | 服务端只强制 R4/R5/R6；本机数据靠 `user_id` 隔离 | 简单、符合红线 |
| B | 把 R1/R2 也同步到云端，服务端统一校验 | 要做云同步，且与「私域不上传」冲突 |

### 6.2 Member 能不能改本机安装

本机是自己的电脑，把安装权限收回给 Owner 意味着多成员共用一台机器时普通成员装不了软件。
建议：**Member 可以改本机安装**，服务端只管目录（能装什么由 Owner/Admin 定）。

### 6.3 Admin 之间能否互相管理

建议：**不能**。防止两个管理员互删导致失联，只有 Owner 能调整 Admin。

### 6.4 备份与恢复

建议：**恢复只给 Owner**，Admin 可触发备份与查看备份记录，但不能恢复、不能下载。
如果你希望 Admin 也能恢复，请说明理由。

### 6.5 越权审计保留多久

建议：**180 天**，与现有审计策略一致；超期由回收任务清理。

---

### 6.6 已确认的决策

| 编号 | 决策 | 结论 |
|---|---|---|
| 6.1 | 服务端强制范围 | **A**：只强制 R4/R5/R6；本机数据靠 `user_id` 隔离 |
| 6.2 | Member 能否改本机安装 | **能**：本机是自己的电脑，目录由管理员定 |
| 6.3 | Admin 之间能否互管 | **不能**：只有 Owner 能调整 Admin |
| 6.4 | 谁能恢复备份 | **仅 Owner**；Admin 可触发与查看备份记录 |
| 6.5 | 越权审计保留期 | **180 天** |

---

### 7.1 备份的一个已知副作用

恢复会重灌 `users` 表，外键级联清空 `sessions` —— **恢复后所有人需要重新登录**。
这是预期行为（恢复意味着整库回到过去），但要在界面上告知。
