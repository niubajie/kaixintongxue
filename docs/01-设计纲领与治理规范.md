## 0. 一页速览

一句话：**在用户给出的钱、时间、资源、执行力约束下，给出一个能落地、每步可验证、随时可纠偏的最优方案。**

产品不是一个聊天框，是**带刹车的执行助手**：默认只出清单，对外动作必须人点头，跑偏了机器自己先发现。

| 维度 | 一句话 | 判据落在哪 |
|---|---|---|
| 适用域 | 有目标、可验证、可回退的执行型任务 | §1.2 |
| 红线 | 六条，代码强制，任何配置都改不了 | §1.1 |
| 责任 | 助手对"未提示的风险"负责，用户对"自主决定"负责 | §1.3 |
| 愿景 | 约束下的可落地最优解，不是理论最优解 | §2 |
| 指标 | 一次过率、单次成本、越界事件、偏差可见时延 | §3.2 |
| 记忆 | 五类、带来源与置信度、可查可改可删 | §5 |
| 纠偏 | 四维偏差 + 四级动作 + 五要素 + 四卡点 + 三触发源 | §6 |
| 钱 | 三档定价 + 十项成本控制 + 网关硬上限 | §7 |
| 技术 | 决策层自研，基础设施对接 | §8.1 |
| 功能区 | 交互 / 技能 / 安全 / 计费可观测 / 自我进化 | §8.4 |
| 阶段 | V1 跑通 → V2 扩展 → V3 完整，阶段门四问 | §9 |

**阅读指引：** 决策者看 §0、§1、§9、§11；研发看 §5、§6、§8；运营与定价看 §3、§7。

**八条不可协商项：**

1. 六条红线写进代码，不写进提示词（§1.1）。
2. 未分类动作默认按 L2 处理（§6.2）。
3. 分级拿不准时升一级，不降级（§1.4）。
4. 每个对外动作必须有一次性确认令牌（§6.3）。
5. 钱、消息、文件、承诺四个不可逆点之前必须设卡（§6.6）。
6. 自我进化不得修改红线、分级、计费单价、安全策略（§8.4.5）。
7. 没有留痕的"用户自主决定"不成立（§6.8）。
8. 指标不达标，不许用"用户没采纳"解释（§3.4）。

## 1. 适用域与边界

### 1.1 红线清单

初稿的六条保留，补上"什么时候判、靠什么拦、违反了怎么办"——否则它只是文案。

| # | 红线 | 判定点（什么时候判） | 拦截方式 | 违反后果 |
|---|---|---|---|---|
| R1（1.1） | 未经用户确认，不执行任何对外动作 | 动作进入执行队列前 | 一次性动作令牌 + 服务端二次校验；无令牌直接 403 | P0 事故，24h 内复盘 |
| R2（1.2） | 不伪造资质、凭证、评价、检测结果 | 生成内容的输出闸门 | 断言必须绑定 evidence_ref；无证据的"已检测／已认证／已好评"替换为"待确认" | P0 |
| R3（1.3） | 不替用户做不可逆决定 | 意图识别 + 动作分级 | 命中 L3 只输出选项与后果，不生成可直接签署／提交的文本 | P0 |
| R4（1.4） | 不越过授权范围读取或上传数据 | 每次工具调用与文件访问 | 调用带 scope；只读用户显式选中的对象；上传前列清单与目的地 | P0 |
| R5（1.5） | 医疗、法律、金融只给参考信息 | 领域意图命中 | 固定模板：信息 + 风险 + 需专业人士；禁止剂量、诊断、胜诉率、收益承诺 | P1 |
| R6（1.6） | 不协助规避平台规则或风控 | 技能与工具调用前 | 拒绝清单：验证码、指纹伪造、多账号轮换、限流绕过、刷量 | P0 |

三条补充规则，缺一条红线就守不住：

- 红线是代码里的 if，不是提示词里的 please。每条红线至少有一个拒绝用例，进回归测试。
- 红线只能通过"改代码 + 升本文版本"修改。用户设置、技能包、灰度开关、自我进化都不能改。
- 拒绝要说清原因和替代路径。"不行"不是合格回答，"这条我不能做，但你可以这样"才是。

### 1.2 适用域

先划"能接什么"，再谈"做多好"。

| 适用场景 | 典型输入 | 交付物 | 为什么适合 |
|---|---|---|---|
| 学习／考试规划 | 目标、时间、基础 | 计划表 + 每日任务 + 检查点 | 结果可验证，过程可回退 |
| 软件部署与排障 | 设备信息、报错 | 检测报告 + 部署清单 + 回滚步骤 | 步骤确定，失败可见 |
| 内容发布准备 | 素材、账号、目标 | 选题 + 脚本 + 发布清单（不代发） | 人做最后一下，风险可控 |
| 店铺数据整理 | 后台截图、报表 | 指标看板 + 异常清单 | 只读，不改对方系统 |
| 资料检索与对比 | 文档、链接 | 对比表 + 出处 | 可溯源 |
| 设备／方案选型 | 预算、用途、限制 | 两到三个方案 + 取舍表 | 可比较，可验证 |

| 不适用场景 | 为什么不接 | 替代做法 |
|---|---|---|
| 医疗诊断、用药剂量 | 后果不可逆，责任无法承担 | 给就医指引与问题清单 |
| 诉讼代理、法律意见 | 需执业资质 | 给材料清单与咨询要点 |
| 证券投资建议、代交易 | 高风险 + 持牌要求 | 只做信息整理与风险提示 |
| 代注册、养号、刷量、虚假评价 | 违反平台规则与法律 | 直接拒绝 |
| 伪造资质、检测报告、合同 | 红线 R2 | 直接拒绝 |
| 无人监督的批量对外操作 | 红线 R1、R6 | 改为逐条人工确认 |

**能不能接，问三句：**

1. 结果可验证吗？（有没有验收标准）
2. 过程可回退吗？（有没有中间态）
3. 责任可归属吗？（谁决定、谁承担）

三问有一个"否"，降级为"只给建议，不代执行"。

### 1.3 责任边界

助手提供建议与执行协助，决策权与结果责任归用户。

| 谁 | 负责什么 | 不负责什么 |
|---|---|---|
| 助手 | 风险提示、依据可追溯、执行留痕、越界拦截、纠偏可见 | 用户的目标设定与最终决策 |
| 用户 | 目标、约束、授权范围、最终决定、自主行动后果 | 助手应提示而未提示的风险 |

**"未提示的风险"怎么判**——三条同时成立，才算助手责任：

1. 该风险在同类任务中属于常识，或已被技能包的 risk_notes 收录；
2. 方案／执行记录里没有以文字形式出现；
3. 风险在决策点之前本可以提示。

**提示的格式要求：** 出现在决策之前、具体到"动作 + 后果 + 概率量级"、可留存可回看。免责声明不算提示。

### 1.4 冲突与从严原则

规则打架时不许现场发挥，按这张表判：

| 冲突情形 | 处理 |
|---|---|
| 本文与技能包／站点规则冲突 | 取更严者 |
| 红线与效率冲突 | 红线优先，不设"仅此一次" |
| 用户偏好与安全默认冲突 | 默认值不可被偏好覆盖；只能被显式授权覆盖一次 |
| 分级拿不准 | 升一级（L1 → L2），不降级 |
| 与 `docs/09`、`docs/10` 的禁止清单 | 那两份是本文在具体场景的细化；不冲突时同时生效 |

## 2. 设计愿景

**在有明确约束（钱、时间、资源、执行力）的前提下，给出一个能落地、每步可验证、随时可纠偏的最好方案。**

把"最好"操作化，四个条件同时满足：

| 条件 | 判据 |
|---|---|
| 可执行 | 每个步骤有明确动作、所需资源、预计耗时 |
| 可比较 | 至少给两个方案，标清成本／时间／风险的差异 |
| 可验证 | 每步都有"怎么算做成了" |
| 可回退 | 每个不可逆点之前有回退路径 |

三条推论：

1. 先给最小可执行清单，再谈优化。清单必须可勾选、可导出、可指派。
2. 每条建议都带成本与时间。不带数的建议等于没给。
3. 方案里必须写明"什么情况下这个方案作废"。

**反模式（出现即打回）：**

- 完美但没人执行得动；
- 只给一个方案，用户无法比较；
- 全流程一次性交付，中间没有检查点；
- 建议里没有风险项。

初稿说"随时可纠偏"——落地机制就是第 6 节。

## 3. 设计目标

### 3.1 三阶段目标

| 阶段 | 交付什么 | 达标线 | 明确不做 |
|---|---|---|---|
| **V1 跑通版** | 文字／语音／图片输入 → 文字／语音／图片输出；只出方案卡与清单，不自动执行 | 追问 ≤ 1 次；单轮文字成本 ≤ ¥0.05（目标 ¥0.02），语音 ≤ ¥0.8/分钟（目标 ¥0.5）；一次过率 ≥ 60%；越界 0；首字 P95 ≤ 2s | 视频生成、3D 人物、3D 场景、实时画面流、自动代办、对外动作 |
| **V2 扩展版** | 加文件与视频输入；加 L2 对外动作（发消息／填表／发布），全部人工确认 | 成本不升（文字 ≤ ¥0.05/轮，语音 ≤ ¥0.8/分钟）；越界 0；偏差当天可见（≤ 24h）；L2 确认覆盖率 100% | 3D 场景、方言全覆盖、无人监督批量操作 |
| **V3 完整体** | 3D 人物解说、3D 场景、实时画面流、方言 | 四条指标全部达线：一次过率 ≥ 85%、单次成本 ≤ V1 的 1.5 倍、越界 0、语音端到端 P95 ≤ 3s | 生成式视频（成本不可控）、全方言、无审核的开放技能市场 |

> 注意 V3 也没写"视频生成"——`docs/00` 已判定单条 ¥10–100 且质量不稳，这一项在 V3 也不做。

### 3.2 指标口径（不定义口径的指标等于没有）

四条核心指标：**一次过率、单次成本、越界事件、时延**。另外两个是过程指标，用来解释核心指标为什么变差。

| 指标 | 定义 | 统计方式 | 采样 |
|---|---|---|---|
| 一次过率 | 用户未要求重做、且未做语义级改写的会话占比 | 会话结束 24h 后三分类：采纳／微调／重做；"微调"不计入一次过 | 全量 + 每周人工抽检 30 条 |
| 单次成本 | 一次交互（含检索、模型、ASR／TTS、存储）的完全成本 | usage_records 汇总；不含人力与固定成本 | 全量 |
| 越界事件 | 未授权对外动作、超范围读取、未确认写入的次数 | 每条必须有审计记录，分"发生／拦截／漏放" | 全量 |
| 时延 | 文字看首字延迟，语音看端到端响应 | 网关与端上双埋点，取 P95 | 全量 |
| 追问次数（过程） | 同一任务内助手主动提问的轮次 | 只统计"信息缺口型"提问，澄清歧义不算 | 全量 |
| 可用性（过程） | 成功响应（非 5xx、非超时）请求占比 | 网关侧统计，按端分 | 全量 |

**追问 ≤ 1 次的操作定义：** 首轮必须用一次追问把缺口问全（输出结构化缺口清单）；第二轮不得再问，缺项按默认假设执行并在产物中标注假设。出现第二次追问即视为设计缺陷，进缺陷库。

### 3.3 达标线是怎么算出来的

成本上限不能拍脑袋，从定价反推：

```
单轮收入 = 档位月费 ÷ 月内含轮次
成本上限 = 单轮收入 × (1 − 目标毛利率)
```

以标准档为例：¥39／月、含 1000 轮文字 → 单轮收入 ¥0.039，按 50% 毛利 → 成本上限约 ¥0.02。
再留 2.5 倍冗余（重试、长上下文、多模型）→ **硬上限 ¥0.05/轮**，超过就由网关降级，不硬扛。

语音同理：¥1.0／分钟 → 成本上限 ¥0.5／分钟；语音按分钟计费、长尾波动小，冗余取 1.6 倍 → **硬上限 ¥0.8／分钟**。

> 这些价格是**建议初始值**，见第 11 节待拍板事项。定价一变，本节数字跟着重算——所以不要再把数字抄到别处去。

### 3.4 防止指标失真

指标一旦变成考核，就会被优化成它自己。

1. 不许为压低追问次数而减少必要提问——缺信息就按假设执行并标注假设。
2. 不许隐藏失败：失败会话必须留在分母里。
3. 不许缩小样本或换统计口径来"达标"。
4. 不许把"用户没采纳"一律解释为"用户不会用"——先看方案本身是不是不成立。

## 4. 交互形态

### 4.1 信息输入

| 输入 | 采集方式 | 前置条件 | 失败降级 |
|---|---|---|---|
| 文字 | 文本输入、粘贴 | 无 | — |
| 文件 | 文件选择器，只读用户选中项 | 用户显式选择 | 超大文件分片／先摘要 |
| 图片 | 相册、拍照、截图 | 相机权限 | 压缩后上传，保留原图引用 |
| 语音 | 按住说话（V1）→ 真双工（V2 起） | 麦克风权限 + AEC | 录音上传转写；不可用转文字 |
| 屏幕实时画面 | 屏幕共享 | 系统录屏授权，按窗口而非全屏 | 截帧 + 用户手动画框 |
| 摄像头实时画面 | getUserMedia／原生相机 | 相机权限 | 降级为拍照 |

### 4.2 信息输出

| 输出 | 用途 | 成本量级 | 首个可用阶段 |
|---|---|---|---|
| 文字 | 主载体：方案、清单、解释 | 极低 | V1 |
| 语音 | 边做事边听、朗读 | ¥0.2–1／分钟 | V1 |
| 图片 | 标注、对比图、报表截图 | ¥0.01–0.1／张 | V1 |
| 预制视频片段 | 讲解类内容拼接 | 近零（素材库） | V1 |
| 3D 人物解说 | 讲解陪伴 | 端侧渲染，边际近零 | V3 |
| 3D 场景 | 空间示意、设备布局 | 建模成本高 | V3 |
| 生成式视频 | — | ¥10–100／条 | **不做** |

原则：能用文字说清的不上语音，能用图片说清的不上视频，能用预制的不做生成。

### 4.3 交互原则

1. **一次问清：** 首轮补齐所有缺口，不许挤牙膏。
2. **结构化：** 方案卡 + 清单 + 风险 + 下一步，固定四块。
3. **可打断：** 任何长任务都有"停"和"改"。
4. **可回退：** 每个产物有版本，回到上一版不超过两次点击。
5. **可复制：** 输出能整块复制／导出，不做截图式交付。
6. **不装懂：** 不知道就标注"待确认"，不用流畅的废话填满。

### 4.4 模态降级矩阵

| 不可用 | 降级到 | 用户可见提示 |
|---|---|---|
| 语音 | 文字 + 可点朗读 | "语音暂不可用，已转文字" |
| 真双工 | 半双工 | "已切换为按住说话" |
| 摄像头 | 拍照 | "已改为拍一张" |
| 3D 人物 | 静态头像 + 语音 | "3D 渲染不可用，已用头像模式" |
| 视频输入 | 关键帧图片 | "已抽取 6 帧分析" |

## 5. 记忆与用户资产

### 5.1 先明确：记忆是助手的，资产是用户的

| | 记忆 | 用户资产 |
|---|---|---|
| 是谁的 | 助手的内部状态 | 用户的 |
| 干什么用 | 让助手少问、不重复问 | 用户要能带走、能复用 |
| 典型内容 | 偏好、进度、已排除的方案 | 方案文件、清单、客户名单、历史记录 |
| 用户权利 | 可查、可改、可删 | 可导出、可迁移 |
| 销号之后 | 随账号删除（审计摘要保留） | 可导出带走 |

### 5.2 记什么：五类，按价值排序

| 类别 | 记什么 | 为什么 | 保留 |
|---|---|---|---|
| **改动痕迹** | 用户把方案改了哪里（diff） | 最值钱：改动是真实意图的证据 | 永久（随资产） |
| **已排除项** | 试过但不行的方案、踩过的坑 | 防止重复推荐废方案 | 1 年，可续 |
| **进度** | 做到第几步、卡在哪 | 决定"一句话就能开工" | 随任务 |
| **档案** | 设备型号、业务范围、家庭情况 | 省掉基础信息回填 | 1 年，用户可改 |
| **偏好** | 表述习惯、忌讳、沟通风格 | 影响体感，不影响正确性 | 6 个月，可删 |

### 5.3 每条记忆的字段设计

| 字段 | 类型 | 必须有的理由 |
|---|---|---|
| content | text | 内容本身 |
| source | enum：user／inferred／system／tool | **最关键**：推断必须和用户明说分开 |
| confidence | 0–1 | 低置信只能当参考，不能当事实用 |
| sensitivity | none／personal／sensitive | 决定要不要额外保护 |
| evidence_ref | string | 推断依据：哪句话、哪次操作 |
| expires_at | timestamptz | 判断是否过时 |
| deletable | bool | 有些能删，有些要留审计 |
| superseded_by | uuid | 冲突时保留演化链 |
| 时间 | created_at／updated_at | 什么时候记的、什么时候改的 |

**写入规则：**

- `source=user` → 置信 1.0，可直接当事实用。
- `source=inferred` → 置信 ≤ 0.6，只进"参考区"；使用时必须显式措辞（"我记得你之前…"）。
- `source=system/tool` → 事实类，带 TTL，过期需重新检测。
- 推断不得升级为事实，除非用户确认。

**读取规则：**

- 每轮注入 ≤ 8 条、≤ 600 tokens，按"改动痕迹 > 已排除 > 进度 > 档案 > 偏好"排序。
- 低置信记忆不进入系统提示的"事实"段。

**冲突规则：**

- 用户明说 > 行为推断；同源取新；高置信覆盖低置信。
- 覆盖不物理删除，写 `superseded_by` 保留演化链——这正好是"改动痕迹"的来源。

**遗忘规则：**

- 过期自动归档；用户删除即时生效（审计只留动作摘要，不留正文）。
- 敏感记忆单独加密，导出时默认不含。

### 5.4 用户资产

| 资产 | 形态 | 导出格式 | 可否迁移 |
|---|---|---|---|
| 方案与清单 | 结构化文档 | Markdown ／ JSON | 可 |
| 客户名单 | 表格 | CSV | 可（导出需二次确认） |
| 历史记录 | 会话与执行日志 | JSONL | 可 |
| 技能配置 | 启用的技能与参数 | JSON | 可 |
| 授权凭证 | 站点 token | 不导出 | 只导出"需重新授权的站点清单" |
| 记忆 | 助手内部状态 | JSON（用户可读） | 可，随账号迁移 |

**边界测试（一句话判断归属）：** 删掉助手，用户还能拿走并能复用的，是资产；拿不走的，是记忆。

### 5.5 隐私与合规

- **最小化：** 只记完成任务必需的信息。
- **不跨用户：** 记忆按 `user_id` 隔离，禁止跨账号检索。
- **不训练：** 默认不用于模型训练；要用于训练必须单独明示同意。
- **私域文档：** 不提供批量导出接口，每次读取写审计（与 `AGENTS.md` 安全红线一致）。

## 6. 人在回路与纠偏机制

### 6.1 第一步：定义"偏"

不定义这个，后面所有机制都不成立——助手自己也不知道什么时候该报警。

| 偏什么 | 判据 | 阈值 | 检测点 | 动作 |
|---|---|---|---|---|
| **目标偏** | 当前步骤与 objective 的关联证据缺失，或用户目标已变但计划未同步 | 连续 2 步无关联证据 | 每步执行后 | 暂停并复述目标，请用户确认 |
| **预算偏** | 累计花费 ÷ 用户声明预算 | ≥ 80% 预警；≥ 100% 硬停 | 每次计费前 | 预警／停止；追加预算需显式操作 |
| **时间偏** | 实际进度 vs 计划 | 落后 > 20% 或 > 1 个工作日 | 每日巡检 | 重排计划或缩范围，二选一 |
| **范围偏** | 出现方案清单外的交付项 | 任何一项（哪怕免费） | 提交前 | 标记并询问"要不要保留" |

第四种最常见也最隐蔽：没人反对，但钱和时间都跑掉了。**范围偏必须按"项"计数，不能按"感觉"。**

### 6.2 第二步：分级，不要一刀切

把"要不要人确认"做成四个层级，判据一句话：**不可逆性、外部可见性、涉及金额或他人利益——任一项为高，就升一级。**

判定树（三问，任一"是"升级）：

```
动作是否可逆？           否 → 至少 L2
动作是否外部可见？       是 → 至少 L2
是否涉及金额／他人利益？  是 → 至少 L2
命中 L3 清单？           是 → L3
以上皆否 → L0 或 L1（按是否有副作用区分）
```

**默认规则：未分类动作一律按 L2 处理（fail-safe）。**

| 层级 | 定义 | 适用 | 实现 |
|---|---|---|---|
| **L0 全自动** | 内部动作，错了也无痕 | 整理资料、生成草稿、做计算 | 直接执行，留日志 |
| **L1 事后可撤** | 先做，做完即报，一键回退 | 改本地文件、生成清单、重排计划 | 版本快照 + 通知 |
| **L2 事前确认** | 必须人点了才执行 | 发消息、下单、支付、删除、对外提交 | 一次性动作令牌 |
| **L3 禁代决** | 只给选项，不做决定 | 签合同、退货、就医用药、法律处置 | 固定模板 + 转介 |

### 6.3 L2 五类动作：可判定清单

"重要动作"不是判据——换个说法就能绕过去。所以五类都写成可判定条件。

| 类别 | 判定条件（满足任一） | 确认形式 | 留痕 |
|---|---|---|---|
| **发消息** | 内容离开本机或本账号：IM、邮件、短信、评论、站内信、自动回复、定时发送 | 完整正文 + 收件人 + 预览 | 正文哈希 + 收件人 + 时间 |
| **下单／支付** | 任何扣款、订阅、续费、试用、充值、代付；含 0 元下单（占库存／绑协议） | 金额 + 收款方 + 可取消方式 | 订单号 + 金额 |
| **删除** | 不可恢复；或影响他人可见内容；或删除他人数据 | 列出将删除的对象清单 | 对象 ID 列表 |
| **对外提交** | 发布、上传、报名、申请、表单提交、授权回调写操作 | 提交内容全文 + 目标地址 | 请求哈希 |
| **改状态** | 修改他方系统状态：改价、上下架、撤回、改地址、改权限 | 改前／改后对照 | before／after |

**明确不算 L2**（避免"事事确认"把产品做废）：本地草稿、给自己看的清单、可 30 天恢复的软删除、L0／L1 动作。

### 6.4 L3 清单：只给选项

签合同／协议、退货／换货／解约／续约、就医与用药（诊断、剂量、停药）、法律处置（起诉、和解、认罪、放弃权利）、投资交易与借贷、婚姻／离职／移民等重大人身决定。

L3 的输出格式固定三块：**选项**（至少两个）、**每个选项的后果与代价**、**建议咨询谁**。不输出"你应该…"。

### 6.5 第三步：纠偏五要素，一个都不能少

多数人只写"可随时修改"，那不叫机制。

| 要素 | 要写清什么 | 缺了会怎样 | 本文落点 |
|---|---|---|---|
| **可见** | 偏差靠什么暴露 | 没人发现，纠个啥 | §6.1 四维检测 + §6.7 三触发源 |
| **可退** | 退回到哪个状态 | 改乱了收不回来 | 版本快照 + §6.6 文件卡点 |
| **可解释** | 为什么偏了 | 一直改、一直偏 | 归因字段 + 差异说明 |
| **可改** | 改完怎么继续 | 停在半路，方案作废 | 纠偏状态机（§6.9） |
| **谁触发** | 人还是助手 | 互相等，谁都不动 | 触发源归属（§6.7） |

"可解释"最容易被跳过，但它是纠偏能不能收敛的关键。只告诉用户"你说的不对我改了"，他会改十遍还是偏；告诉他"你改的是预算这一项，原方案把它按 X 算了"，一次就改对。

落成字段：

```
deviation:
  id, dimension(goal/budget/time/scope), detected_at,
  detected_by(user/assistant/scheduler),
  evidence, baseline, actual, attribution,
  suggestion, resolved_at, resolution
```

### 6.6 第四步：检查点放哪——后果前置

原则只有一条：**检查点放在"不可逆后果发生之前"那一步。**

| 卡点 | 位置 | 检查什么 | 不通过时 |
|---|---|---|---|
| **钱** | 支付／扣费调用前 | 预算余额、用户确认、金额上限 | 拒绝执行，提示追加预算或换方案 |
| **消息** | 发送 API 前 | 收件人、正文、是否对外 | 拦截，转人工确认 |
| **文件** | 覆盖／删除前 | 版本快照是否已生成、是否可恢复 | 先快照再写，失败即中止 |
| **承诺** | 生成对外承诺文本前 | 是否含交付时间、金额、保证性措辞 | 改为"建议措辞"，由用户拍板 |

四个卡点之外放手让它跑（L0／L1），否则人会烦。

### 6.7 第五步：三个触发源

| 触发源 | 什么时候响 | 归属 | 时延要求 |
|---|---|---|---|
| **用户叫停** | 随时 | 人的权利，必须随时可用 | 0.5s 内生效，状态不丢 |
| **助手自检** | 四维偏差任一超阈值 | 前面定义的四维就是判据 | 每步后（≤ 1s 本地规则） |
| **定时回看** | 每日一条进度；每阶段一次复盘 | 防"第 10 天才发现偏" | 每日 1 次 + 阶段结束 |

第二类必须存在。只靠用户自己发现问题，等于没做回路——"随时可纠偏"里的"随时"，靠的是机器自己在盯。

### 6.8 第六步：留痕

每次纠偏记四件事：谁改的、什么时候、改了什么、为什么。

| 字段 | 说明 |
|---|---|
| actor | 用户／助手／系统（定时） |
| action | 偏差类型 + 动作（预警／暂停／改方案／追加预算） |
| before／after | 关键字段前后值（方案摘要、预算、时间线） |
| reason | 归因 + 用户原话（可脱敏） |
| hash_chain | 上一条的哈希，append-only |

不是为了审计好看，是为了撑住 §1.3 的责任边界：没留痕，"用户自主决定的结果"这句话说不清楚，出事就变成扯皮。

- 用户可查：时间线视图 + 导出。
- 不可篡改：只追加、哈希链、每日锚定。

### 6.9 纠偏状态机

```
运行 → 触发（偏差／叫停） → 暂停 → 归因
     → 二选一（改方案／改约束） → 确认 → 恢复运行
                              └→ 无法收敛 → 终止并交付已完成部分
```

状态必须持久化：断线、重启、换端都能续上；恢复时必须复述"刚才改了什么、为什么"。

## 7. 付费与成本策略

### 7.1 定价分层

建议初始值（第 11 节待拍板）：

| 档位 | 价格 | 包含 | 超额 | 目标用户 |
|---|---|---|---|---|
| 免费 | ¥0 | 文字 30 轮／日、语音 3 分钟／日；本地模型不限量 | 次日恢复，不累积 | 试用、验证价值 |
| 标准 | ¥39／月 | 文字 1000 轮、语音 60 分钟、文件与知识库 | ¥0.05／轮、¥1.0／分钟 | 个人重度使用 |
| 专业 | ¥129／月 | 3000 轮、180 分钟、多模型辩论、报表导出 | 同上 | 小团队、内容创作者 |
| 企业 | 定制 | 离线包、私有部署、审计导出、SSO | 合同约定 | 有合规要求的团队 |

**定价原则：**

1. 成本加成打底（毛利率 ≥ 50%），价值定价封顶（用户省下的时间与钱）。
2. 按"轮次 + 分钟 + 次"计量，不按 token 计量——用户看不懂 token。
3. 免费额度按设备 + 手机号双维度限，防批量注册。
4. 学生／教育场景单独折扣，走人工审核，不开放自助。

**"按愿意支付的成本给最好方案"的落地：** 同一个需求，按预算出三档，并写清每档放弃了什么——

| 方案档 | 默认做法 | 交付差异 | 适合谁 |
|---|---|---|---|
| 省钱档 | 本地／便宜模型 + 缓存 + 夜间批处理 | 慢一点、模型弱一点，清单与结论不变 | 预算紧、不赶时间 |
| 均衡档 | 标准模型 + 关键步骤升级 | 速度与质量平衡 | 大多数个人用户 |
| 省时档 | 旗舰模型 + 并行 + 人工兜底 | 最快、最全，成本最高 | 时间比钱贵 |

三档不是三个产品，也不是三个订阅档，而是同一套编排的三种参数组合——否则维护量会翻三倍。

### 7.2 成本控制手段

钱不是省出来的，是设计出来的。十项手段按"先做后做"排序：

| # | 手段 | 做法 | 省多少（量级） | 风险 |
|---|---|---|---|---|
| 1 | 模型分级路由 | 默认便宜模型，升级需触发（长文／失败重试／用户选择） | 50–90% | 质量下降，需 A/B |
| 2 | 语义缓存 | 同问题／同图／同文档命中直接复用 | 10–30% | 答案过期，需 TTL |
| 3 | 结果缓存 | 技能产物（报表、清单、预制视频）按输入哈希复用 | 20–40% | 个性化不足 |
| 4 | 上下文裁剪 | 摘要 + 滑窗 + 引用片段，不塞全文 | 30–60% | 丢关键信息，需引用锚 |
| 5 | 批量与异步 | 非实时任务进队列，夜间跑 | 10–30% | 用延迟换成本 |
| 6 | 降级阶梯 | 旗舰 → 标准 → 本地 → 模板 | 兜底 | 体验断崖 |
| 7 | 预算护栏 | 用户级／全局日预算，超限熔断 | 防超支 | 可能误伤大客户 |
| 8 | 预扣 + 结算 | 调用前预扣额度，完成后按实结算退差 | 防坏账 | 并发下需幂等 |
| 9 | 反滥用 | 设备指纹、频控、验证码、异常行为识别 | 防刷 | 可能误判正常用户 |
| 10 | 成本异常检测 | 单用户／单模型成本突增 > 3σ 触发限流与告警 | 防跑飞 | 需基线数据 |

**两条硬规则：**

- 网关侧硬上限：单次请求预估成本超过上限，直接降级或拒绝，不"先跑了再说"。
- 每笔成本必须落到 `usage_records`，可追溯到用户、会话、模型、技能。

### 7.3 计费正确性

- **幂等：** 同一 `request_id` 只记一次账。
- **对账：** 日结，平台账单 vs 内部汇总差异 < 0.5%；超了先停结算再查。
- **退款：** 失败调用自动退预扣；争议人工处理并留痕。
- **透明：** 用户能看到"这一轮花了多少"，后台能看到"这一轮赚了多少"。

## 8. 技术路线与实施方案

### 8.1 自研 / 对接的划分原则

判据四条，逐条回答后归属自然清楚：

| 判据 | 倾向自研 | 倾向对接 |
|---|---|---|
| 是否构成差异化 | 是 | 否 |
| 是否承担合规责任（审计、拦截、留痕） | 是 | 否 |
| 是否有稳定商用服务且成本可控 | 否 | 是 |
| 自建后能否长期维护（一人可维护） | 是 | 否 |

| 能力 | 选择 | 理由 | 替换成本 |
|---|---|---|---|
| 编排与技能调度 | **自研** | 产品骨架，决定体验 | 高 |
| 记忆与纠偏 | **自研** | 差异化，且直接对应责任边界 | 高 |
| 方案生成规则库 | **自研** | 领域知识沉淀，别人替不了 | 中 |
| 模型网关 | **自研（薄）** | 控成本、可换供应商、统一计费 | 中 |
| 权限与审计 | **自研** | 合规底线，不能外包 | 低（但必须做） |
| 基础模型 | 对接 | 训练不自研 | 低（网关抽象） |
| ASR／TTS | 对接 | 商用成熟，成本低 | 低 |
| 实时音视频 | 对接（TRTC／Agora） | 自研 6 人月起 | 中 |
| 支付 | 对接 | 合规与对账 | 低 |
| 对象存储／CDN | 对接 | 基础设施 | 低 |
| 页面自动化 | 用 Playwright | 不自研浏览器内核 | 低 |
| 3D 渲染 | 用现成引擎 | 不自研渲染器 | 中 |

**禁止自研：** 基础大模型训练、实时音视频、支付通道、语音识别底层。

**新依赖准入：** 说明理由 + 评估替换成本 + 许可证核查 + 体积与启动影响。

### 8.2 交付物定义

每个阶段交付五类东西，缺一类不算完成：

| 类型 | 内容 | 验收方式 |
|---|---|---|
| 可运行版本 | 桌面／网页（V2 起含手机）可安装可启动 | 从零安装一遍 |
| 配置与清单 | 技能包、模型路由、站点页面地图 | 配置校验脚本通过 |
| 文档 | 变更说明、已知限制、回滚步骤 | 与本文及相关 docs 不冲突 |
| 指标看板 | 一次过率、成本、越界、时延 | 看板能出数，口径与 §3.2 一致 |
| 验收脚本 | 红线拒绝用例、L2 拦截用例、降级用例 | 自动化跑通，失败即阻断发布 |

**DoD（完成的定义）五条：** 能跑（装得上）、能验（脚本过）、能退（回滚有步骤）、能看（指标有数）、能讲（文档写清限制）。

### 8.3 失败与降级策略

| 失败 | 探测 | 降级动作 | 用户可见 | 恢复 |
|---|---|---|---|---|
| 模型超时（> 8s） | 网关计时 | 换供应商重试 1 次 → 便宜模型 | "已切换更快的模型" | 上游恢复后回切 |
| 限流 429 | 状态码 | 指数退避 ≤ 2 次 → 异步排队 | "排队中，稍后通知" | 队列消费 |
| 输出不合规 | 输出闸门 | 重新生成 ≤ 2 次 → 模板兜底 | "这条我换个说法" | 人工复核 |
| 工具失败 | 返回值／截图 | 停止该步，保留现场 | 失败截图 + "改用人工" | 修复后从断点续 |
| 凭证过期 | 401 | 转"需重新授权" | 授权卡片 | 重新授权 |
| 预算耗尽 | 计费检查 | 暂停非 L0 动作 | "额度不足，可充值或换本地模型" | 充值或降级 |
| 存储损坏 | 完整性校验 | 回滚最近快照 | "已恢复到 X 时点" | 告警 + 人工排查 |
| 网络中断 | 心跳 | 本地队列 + 断点续传 | "离线，恢复后继续" | 网络恢复 |

**重试预算：** 同一动作 ≤ 2 次，指数退避，幂等键必带。超过就降级或转人工，不无限重试。

### 8.4 功能区划分

整个系统按职责切五块，块间只走规定接口。

### 8.4.1 交互功能区

| 项 | 内容 |
|---|---|
| 职责 | 采集输入、渲染输出、会话编排（意图 → 技能选择 → 结果呈现） |
| 允许 | 申请权限、格式转换、流式渲染、维护会话状态 |
| 禁止 | 直接调外部工具、直接读写业务库、绕过输出闸门、自己裁决分级 |
| 接口 | 向内：`policy.Check(action)`、`billing.Reserve()`；向外：技能执行请求 |
| 失败 | 输入不可用 → 降级矩阵；渲染失败 → 纯文本兜底 |

### 8.4.2 技能实施区

| 项 | 内容 |
|---|---|
| 职责 | 执行六个原语（Auth／Browser／AppCall／Render／Install／Store），产出可验收结果 |
| 允许 | 沙箱内操作文件与浏览器、经网关调用外部 API |
| 禁止 | 自定计费、自改权限、跳过动作令牌、无头批量操作、代注册代填密码 |
| 接口 | `policy.Authorize()` → `action.Execute(token)` → `billing.Settle()` |
| 失败 | 单步失败即停，保留截图／日志／中间产物，可从断点续 |

### 8.4.3 安全防范区

三件事，各自有硬指标：

| 子域 | 防什么 | 手段 | 验收 |
|---|---|---|---|
| 防黑客 | 越权、注入、重放、依赖投毒 | 鉴权、最小权限、参数化查询、CSP、依赖审计、密钥托管 | 渗透测试无高危；越权用例全拦 |
| 防自我误删 | 误删、误覆盖、批量删除、模型幻觉执行删除 | 软删除 + 回收站 30 天 + 写前快照 + 禁止全表删 + L2 令牌 | 删除可恢复；批量删除需双确认 |
| 防存储坏损 | 磁盘坏道、写入中断、迁移失败 | SQLite WAL + 每日快照 + 完整性校验；云端 PITR + 定期演练 | 每季度恢复演练 1 次，RPO ≤ 24h |
| 审计链 | 事后说不清 | append-only + 哈希链 + 每日锚定 | 任意一条可验证未被篡改 |

安全区是横切面：所有对外动作都从这里过一遍，没有例外。

### 8.4.4 计费与可观测区

| 项 | 内容 |
|---|---|
| 职责 | 预扣／结算、配额、用量、追踪（traceId）、告警、成本看板 |
| 允许 | 拒绝超预算请求、触发熔断、写 `usage_records` |
| 禁止 | 修改业务逻辑、暗改价格、跳过幂等 |
| 指标 | 计费差异 < 0.5%；成本可见时延 ≤ 5 分钟；告警到达 ≤ 1 分钟 |

### 8.4.5 自我进化区

**只改"策略层"，不改"约束层"。**

| 能改 | 不能改 |
|---|---|
| 提示词版本、模型路由权重、技能排序、允许区间内的阈值、界面文案 | 六条红线、L0–L3 分级、计费单价、安全策略、审计规则、删除与保留策略 |

进化流程（缺一步不许上线）：

```
指标异常/机会 → 生成候选配置 → 影子模式（不生效，只记录）
  → 小流量灰度（≤5%） → 护栏对比（一次过率不降、成本不升、越界=0）
  → 人工批准 → 全量 → 保留回滚点
```

- **护栏：** 任一指标劣化超阈值（一次过率 −3pt、成本 +10%、越界 > 0）自动回滚。
- **进化日志：** 记录"改了什么、为什么、效果如何、谁批准"。
- **硬检查：** 发布前 diff 必须命中白名单字段；命中黑名单字段直接构建失败。

### 8.5 区域调用规则

| 调用方 → 被调方 | 允许 | 约束 |
|---|---|---|
| 交互 → 技能 | 是 | 必须带 policy 令牌 |
| 交互 → 计费 | 是 | 只读余额 + 预扣 |
| 技能 → 计费 | 是 | 只记账，不改价 |
| 技能 → 安全 | 是 | 每次动作判级 + 审计 |
| 进化 → 配置中心 | 是 | 只写候选版本 |
| 进化 → 运行态 | **否** | 必须经发布器 + 人工批准 |
| 进化 → 安全／计费规则 | **否** | 黑名单，构建即失败 |
| 任意区 → 外部工具 | **否** | 统一出口：技能区经网关 |

## 9. 分阶段路线

> 排期唯一权威是 `docs/04` 第 9 节（P0–P8）。本节只定义能力阶段的**进入／退出条件**，不另写一份排期——同一份排期写两处，必然有一处先过期。

### 9.1 双轨映射

| 能力阶段 | 对应 P 阶段 | 进入条件 | 退出条件（达标线） |
|---|---|---|---|
| **V1 跑通** | P1–P2、P4 | P0 竖切可用；红线拦截与 L 分级有代码；`usage_records` 落库 | §3.1 V1 全部达标；红线拒绝用例全过 |
| **V2 扩展** | P3、P5–P7 | V1 退出条件满足；技能原语最小闭环（Auth + Browser）；审计链可用 | §3.1 V2 全部达标；L2 拦截覆盖率 100%；偏差 ≤ 24h |
| **V3 完整** | P8 | V2 退出条件满足；3D 与实时链路各有独立降级路径 | §3.1 V3 四条指标全部达线 |

### 9.2 阶段门四问（过不了不进入下一阶段）

1. 一次过率达标了吗？（看全量，不看精选样本）
2. 单次成本在硬上限内吗？（含重试与长尾）
3. 越界 = 0 且审计完整吗？（漏放一次就重来）
4. 下一阶段要用的原语，是否已有可复用实现？（没有就先补，不并行开新摊子）

### 9.3 止损线

- V1 结束时一次过率 < 40%，或单轮成本 > 2 倍上限 → 暂停扩端，回炉方案质量与模型路由。
- V2 期间越界漏放 ≥ 1 次 → 停止新增对外动作类型，先补拦截。
- V3 的 3D／实时链路若使成本超 V1 的 1.5 倍且一次过率无提升 → 砍掉，只保留静态头像 + 语音。

### 9.4 每阶段明确不做

| 阶段 | 不做（哪怕用户要） |
|---|---|
| V1 | 对外动作、视频生成、3D、实时流、方言、开放技能市场 |
| V2 | 3D 场景、方言全覆盖、无人监督批量操作、代注册／养号 |
| V3 | 生成式视频、全方言、无审核的技能上架 |

## 附录 A 术语表

| 术语 | 含义 |
|---|---|
| 红线 | 任何情况下不可越过的行为边界，代码强制 |
| L0–L3 | 动作的四级授权层级：全自动／事后可撤／事前确认／禁代决 |

| 四维偏差 | 目标偏、预算偏、时间偏、范围偏 |
| 检查点 | 不可逆后果发生之前的强制关卡 |
| 一次过率 | 无需重做且无实质改写的会话占比 |
| 硬停 | 达阈值即终止，不可自动继续 |
| 影子模式 | 新策略只记录不生效，用于对比 |
| PITR | 按时间点恢复（Point-In-Time Recovery） |
| RPO | 恢复点目标：最多允许丢多少数据 |
