# 模型与软件部署归属表

> 版本 v1.1 ｜ 回答一个问题：**每个组件装在哪一端，为什么。**
>
> v1.1 修订（评审 P0-1 / P0-3）：临时凭证拆成"上传"与"模型调用"两类，v1 全部中转；
> Ollama 交付方式统一为"按需下载便携版"，引导层只保留 AGPL 与需驱动/系统服务的组件。
>
> 这份表的作用：接新模型、加新功能时不用重新讨论一遍，查表即可。

---

## 0. 三个判断条件

任何一个组件进来，先过这三道：

| 条件 | 判断 | 结论 |
|---|---|---|
| **要不要厂商密钥** | 要 | 只能放服务器 |
| **体积是否 > 100 MB** | 是 | 不能让用户被动下载，做成按需 |
| **是否处理私域内容** | 是 | 必须在用户本机 |

三条全过，位置就唯一了。**没有"凭感觉"的空间。**

## 2. 为什么这么分

### 2.1 服务器必须持有的四类东西

**① 所有厂商密钥**

Tauri 的安装包能解包，前端 JS 是明文。**任何打包进客户端的密钥，一周内就会被薅光。**

**② 计费与配额**

不知道谁用了多少，就没法限流，也没法做付费。

**③ 辩论编排**

要让 3 个模型互相看观点、并行调用、统一收敛。客户端做既暴露密钥，也统一不了账。

**④ 数据出境判断**

`docs/04` 第 4 节规定：私域内容只能走本地模型。这个判断必须在服务端做——客户端的判断可以被绕过。

### 2.2 客户端内置的三样

| 组件 | 为什么内置 |
|---|---|
| Go sidecar | 私域库、文档解析都要它；单文件 20 MB，随手带 |
| ffmpeg | 音视频处理基础能力，用 LGPL 构建避开 GPL 传染 |
| OCR | 拍照识字是核心交互，延迟要低，不能等下载 |

**内置标准：单个 < 50 MB 且几乎人人都会用到。**

### 2.3 按需下载的三样

| 组件 | 体积 | 为什么不能内置 |
|---|---|---|
| Ollama | 800 MB | 加上模型就是 5 GB，安装包直接劝退 |
| 模型权重 | 4.5 GB | 同上，而且大部分人显卡跑不动 |
| Whisper | 150 MB–1.5 GB | 只有少数用户需要本地转写 |

**按需下载的关键是"别吓到用户"**：默认不下载，用户选了对应功能才提示。

## 3. 本地模型的首次使用流程

这是最容易做砸的一段。用户第一次点"开启本地模型"时：

```
[1] 检测 127.0.0.1:11434 是否有响应
   ├─ 有 → 跳到 [3]
   └─ 没有 → 到 [2]

[2] 下载并解压 Ollama（便携版）
   文案：「本地模型需要先安装 Ollama（约 800MB），装完数据就永远留在你电脑上」
   ├─ [去下载] 打开浏览器到 ollama.com
   └─ [我已安装] 重新检测

[3] 检测是否有可用模型
   ├─ 有 → 可用
   └─ 没有 → 提示选模型
         ├─ Qwen 7B（4.5GB，中文好，推荐）
         ├─ Qwen 14B（8GB，更强，需 12GB 显存）
         └─ 后台下载 + 进度条（可暂停，下次续传）
```

**三条硬要求：**

1. **不要静默下载 5 GB** — 必须用户确认
2. **不要假装装好了** — 检测不到就明说，别让用户以为能用
3. **下载必须可暂停续传** — 5 GB 断一次要从头下，用户会骂人

## 4. 体积与流量估算

### 4.1 安装包

| 内容 | 体积 |
|---|---|
| Tauri 壳（Rust 二进制） | 8 MB |
| 前端产物（React + CSS） | 2 MB |
| Go sidecar | 20 MB |
| ffmpeg | 30 MB |
| OCR | 15 MB |
| 头像 + 图标资源 | 1 MB |
| **合计** | **约 76 MB** |

→ 安装包控制在 **80 MB 以内**，用户可接受。

### 4.2 首次使用时的额外下载

| 场景 | 下载量 |
|---|---|
| 只用云端模型 | 0 |
| 开启本地模型 | 800 MB + 模型 4.5 GB |
| 开启本地语音转写 | 追加 150 MB–1.5 GB |

**大多数用户第一次只走云端，下载量是 0。** 这是设计对的标志。

### 4.3 服务器流量（按 1000 日活估算）

| 类型 | 估算 | 费用 |
|---|---|---|
| 文本对话 | 每轮约 5 KB，1 万轮/天 = 50 MB/天 | 可忽略 |
| 图片上传 | 直传对象存储，**不过服务器** | 0 |
| TTS 下行音频 | 每用户 3 分钟/天 ≈ 3 MB，共 3 GB/天 | **约 ¥72/月** |
| ASR 上行音频 | 入网通常不计费或极低 | 可忽略 |

**唯一值得注意的是 TTS 下行流量。** 这也是"默认只给结论配音"的另一个理由（见 docs/05 第 9 节）。

## 5. 安全边界

| 规则 | 说明 |
|---|---|
| 客户端永不持有厂商密钥 | 代码审查必查项 |
| 私域内容默认不出本机 | 服务端强制校验，不依赖客户端标记 |
| 服务器日志不记正文 | 只记 traceId、模型、token 数、耗时 |
| 文件上传（v1） | **由服务器中转**：可审计、可加密、可限流；v2 带宽成为瓶颈后再评估 STS 直传 |
| `.env` 不进 Git | 已在 `.gitignore` |

## 6. 决策流程图

```
新组件要接入
   │
   ├─ 需要厂商密钥？
   │     └─ 是 ──▶ 服务器持有密钥，客户端只发请求
   │
   ├─ 体积 > 100 MB？
   │     └─ 是 ──▶ 按需下载（默认不装，用户选择才下）
   │
   ├─ 处理私域内容？
   │     └─ 是 ──▶ 在用户本机执行，绝不上传
   │
   └─ 以上都不是
         └─▶ 打包进安装包（单文件 < 50 MB 优先）
```

## 7. 三个典型错误

| 错误 | 后果 |
|---|---|
| 把 API Key 打包进客户端"方便调试" | 密钥泄露，账单爆炸 |
| 把 Ollama + 模型一起打进安装包 | 安装包 5 GB，下载转化率减半 |
| 所有东西都放服务器 | "私域不出本机"承诺破产，GPU 成本失控 |

## 8. 演进路径

| 阶段 | 做法 | 触发条件 |
|---|---|---|
| **v1（现在）** | 所有云端调用经服务器中转 | — |
| v2 | 音频/视频走临时凭证直连厂商，省服务器带宽 | TTS 流量费用超过每月 ¥300 |
| v3 | 实时音视频走 RTC 云服务（TRTC / Agora） | 做真双工时 |
| v4 | 端侧推理（WASM / WebGPU）处理轻量任务 | 明确有"必须离线"的场景 |

**v1 不做直连类临时凭证。** 两类凭证要分开看：

| 类型 | v1 做法 | 何时升级 |
|---|---|---|
| 对象存储上传 | **服务器中转**（可审计、可加密） | 出网带宽成为瓶颈，或单文件 > 100 MB 频繁上传 |
| 模型 / 音频 API | **全部经服务器中转**（密钥与计费都在服务端） | TTS 出网费用超过每月 ¥300 再评估直连 |

你现在的量级，服务器带宽不是瓶颈；多一层凭证签发只是多一层 bug。

---

## 9. 一句话总结

> **模型不绑定在任何一端，而是按「密钥 / 体积 / 敏感度」三个条件路由。**
> 服务器管密钥与编排，客户端管私域与重活，大体积组件让用户按需下载。
