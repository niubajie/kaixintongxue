## 0. 一页速览

| 产物 | 语言 | 框架 / 壳 | 代码来源 | 发布形态 |
|---|---|---|---|---|
| 网页（产品） | TypeScript | React + Vite（SPA） | 母版 | 静态托管 + API |

```
                 ┌──────────── 一套 React 母版（src/）────────────┐

                         │             │
              ┌──────────┴──┐   ┌──────┴────────┐

              │ + Go sidecar│   │ + 原生插件    │
```

**语言只有两种：TypeScript + Go。** 壳只做三件事：开窗、给原生能力、打包。

## 1. 为什么是这个组合

### 1.1 一套母版，三个壳

四个产物里，**网页和桌面是同一份构建产物**（区别只在壳），**手机和平板也是同一份**（区别只在断点和原生插件）。

这带来三个直接收益：

- 改一个页面，网页 / 桌面 / 手机 / 平板同时生效
- 只有一个 `node_modules`、一套 TS 类型、一套设计变量
- 一个人维护得动

### 1.2 为什么手机上 Capacitor 而不是 React Native

| 成本项 | Capacitor | React Native |
|---|---|---|
| 现有 9 个页面 | **0 天** | **5–9 天**重写 |
| 后续每个新功能 | 写 1 遍 | **写 2 遍** |
| 现有 CSS（15KB） | 全复用 | 不可用，改 `StyleSheet` |
| `data-tauri-drag-region` / MDL2 图标 | 直接用 | 全部重做 |
| `platform/` 桥接层 | 加一个文件 | 重做 |

**RN 买到的是原生渲染性能，付出的是永久双份 UI 维护。** 在"页面 + 聊天 + 拍照"这个业务形态下，WebView 完全够用。

### 1.3 官网为什么独立用 Astro

产品页不需要被搜索引擎收录，官网需要。二者的技术诉求相反：

- 产品 SPA：首屏是 JS，SEO 无意义，交互优先
- 官网：首屏必须是静态 HTML，内容可被爬

用 Astro 写官网，默认零 JS、构建成纯静态、可以混用 React 组件做个别交互区块。**这两件事不该用同一个工程。**

## 2. 逐端方案

### 2.1 网页（产品）

| 项 | 值 |
|---|---|
| 框架 | React + Vite（SPA） |
| 路由 | **HashRouter**（与桌面保持一致，避免两套行为） |
| 部署 | 静态产物 → 对象存储 / CDN |
| API | 同域 `/api` 反代，避免 CORS |
| 构建目标 | `es2020`（浏览器基线比 WebView2 宽） |

**注意**：网页端与桌面端共用 `platform/` 抽象层。浏览器环境自动降级，更新面板、窗口控制不渲染。

### 2.2 官网

| 项 | 值 |
|---|---|
| 框架 | **Astro** |
| 内容 | Markdown / MDX |
| 交互 | 少量 React 岛（下载按钮、FAQ 折叠） |
| 部署 | 纯静态 → CDN |
| 必含 | 首屏、功能截图、下载页（含 SmartScreen 说明）、隐私政策、更新日志、ICP 备案号 |

### 2.3 Windows 桌面

| 项 | 值 |
|---|---|
| 壳 | Tauri 2 |
| 重活 | Go sidecar（与云端后端同一份代码，`GOOS=windows` 编译） |
| 安装 | NSIS，`installMode: currentUser`，`embedBootstrapper` |
| 更新 | `tauri-plugin-updater` + minisign（免费，无需代码签名证书） |
| CSP | 配置在 `tauri.conf.json`，不用 meta |

详见 `docs/03-桌面端技术方案-Tauri.md`。

### 2.4 手机 + 平板

| 项 | 值 |
|---|---|
| 壳 | **Capacitor** |
| 相机 | `@capacitor/camera`（原生相机，不用 `getUserMedia`） |
| 推送 | `@capacitor/push-notifications` |
| 存储 | `@capacitor/preferences` + `@capacitor/filesystem` |
| 布局 | 同一工程，CSS 断点：`<760px` 手机 / `760–1100px` 平板分栏 / `>1100px` 桌面 |
| 平板 | **先 PWA**（可加到主屏、离线可用），需要上架时再 `npx cap add ios/android` |

```ts
// capacitor.config.ts
import type { CapacitorConfig } from '@capacitor/cli'

const config: CapacitorConfig = {
  appId: 'com.kaixin.assistant',
  appName: '开心同学',
  webDir: 'dist',
  server: { androidScheme: 'https' }
}

export default config
```

**平板的判断**：iPad 上 PWA 体验已接近原生，且省掉一套打包与审核。**先用 PWA 验证，别一上来就打包。**

## 3. 共享层设计

### 3.1 平台抽象层（强制）

```
src/platform/
├── types.ts       DesktopBridge 接口（与壳无关）
├── tauri.ts       Tauri 实现（动态 import）
├── capacitor.ts   Capacitor 实现（动态 import）
├── web.ts         浏览器降级
└── index.ts       探测环境后导出单例
```

探测顺序：

```ts
const env =
  '__TAURI_INTERNALS__' in window ? 'tauri'
  : (window as any).Capacitor ? 'capacitor'
  : 'web'
```

**铁律：组件禁止直接 `import '@tauri-apps/api'` 或 `@capacitor/*`。**

### 3.2 什么共享、什么不共享

| 共享（约 70%） | 不共享 |
|---|---|
| TS 类型、接口契约 | 路由实现（各壳加载方式不同） |
| 业务计算、校验、格式化 | 存储实现（plugin-store / Preferences / sessionStorage） |
| 设计变量（颜色/字号/间距） | 相机与文件选择 |
| 所有 UI 组件 | 更新机制 |
| Zustand store 结构 | 窗口控制 |

### 3.3 数据层

- **服务端数据**：TanStack Query（缓存、重试、失效）
- **客户端状态**：Zustand（当前页、草稿、弹窗）
- **禁止**：把接口数据塞进 Zustand（会失去失效能力）
- **禁止**：Token 放 localStorage（走 `bridge.secureStorage`）

## 4. 实时音视频方案（最关键的一块）

### 4.1 音频约束三件套（必须开）

```ts
const stream = await navigator.mediaDevices.getUserMedia({
  audio: {
    echoCancellation: true,   // 回声消除：解决"自己听到自己"
    noiseSuppression: true,   // 降噪
    autoGainControl: true     // 自动增益
  }
})
```

浏览器和 WebView 都原生支持这三项。**这是"真双工"能否成立的分水岭**——不开 AEC，喇叭声音会被麦克风录回去，导致 AI 自问自答。

### 4.2 分级降级策略

| 优先级 | 通道 | 触发条件 |
|---|---|---|
| 1 | **WebRTC**（UDP，低延迟） | 能力检测通过 |
| 2 | **WebSocket** 流式 | WebRTC 建连失败 / 企业网络禁用 UDP |
| 3 | **HTTP 分段上传** | 以上都不可用 |

能力检测放在 `platform` 层暴露，**不要在组件里判断**。

### 4.3 半双工 vs 真双工

| 模式 | 实现 | 风险 | 建议 |
|---|---|---|---|
| 半双工（按住说） | 录音 → ASR → LLM → TTS | 低 | **v1 先做这个** |
| 真双工（边说边听） | 同时录音 + 播放 + VAD 打断 | AEC 不干净就会自激 | v2 再上，先要求戴耳机 |

### 4.4 端侧 vs 服务端

| 任务 | 放哪 |
|---|---|
| 音频 AEC / 降噪 | **端侧**（浏览器自带） |
| 语音识别 | 服务端（准确率优先） |
| 图像标注渲染 | **端侧 Canvas** |
| 图像理解 / 推理 | 服务端（重活一律上云） |
| 文字向量化 | 服务端 |

**原则：端侧只做"必须实时且足够轻"的事，其余全部上交。**

## 6. 对三份外部提案的取舍

### 采纳

| 来源 | 建议 | 落地位置 |
|---|---|---|
| 图 3 | `getUserMedia` 开 AEC / 降噪 / 自动增益 | `lib/media.ts` |
| 图 3 | WebRTC 主通道 + WebSocket 兜底 | 第 4.2 节 |
| 图 3 | 端侧能力检测后再决定降级 | `platform` 层 |
| 图 3 | 标注用 Canvas 而非 DOM | `components/Annotator` |
| 图 2/3 | 平板用断点布局，不另做一套 | `styles.css` |
| 图 1 | 平板优先 PWA，晚点再打包 | 第 2.4 节 |

### 推迟（附触发条件）

| 建议 | 何时才做 |
|---|---|
| React Native + LiveKit RN SDK | WebView 实测 WebRTC 延迟 > 300ms，或需要后台持续录音，或需要多摄/RAW |
| Next.js 混入产品 | 产品页需要被搜索引擎收录时（目前官网 Astro 已覆盖） |
| 鸿蒙 RNOH | 确定要覆盖鸿蒙时。Capacitor 不支持鸿蒙，**这是唯一必须 RN 的场景** |
| Rust 媒体栈（uniffi / Nitro） | 团队规模 > 3 人且媒体成为核心壁垒时 |

### 拒绝

| 建议 | 理由 |
|---|---|
| 四套壳（Tauri + Next + RN + RNOH） | 一个人维护不动，等于四个产品 |
| Rust 自研音频/相机/NPU | 等于重写一个原生应用 |
| 写死 RN 0.83 / Expo 55 / RNOH 0.77.1 | 版本会过时，写进方案就是埋雷 |
| 桌面端用 Oboe | Oboe 是 **Android** 音频库，Windows 不适用——说明该方案是模板拼贴 |

## 12. 三条不可违反的纪律

1. **只有一种语言写前端。** 不引入 Dart、Kotlin、Swift 写业务 UI。
2. **组件不直接依赖壳。** 一切壳能力走 `platform/`。
3. **一套代码不能变成两套。** 一旦出现"RN 版也要改一下"，立刻停下来评估是否值得。
