## 0. 功能拆解

用户描述的是四个动作，技术上是四件完全不同的事：

| 步骤 | 用户动作 | 技术本质 | 难度 |
|---|---|---|---|
| ① | 点「现有电脑 + AI 技能」 | 读本机硬件 | ★★☆☆☆ |
| ② | 填名称 + 描述，点「配置 AI 软件」 | 自然语言 → 软件匹配 | ★★★☆☆ |
| ③ | 点「生成技能方案」 | 依赖合并 + 冲突检测 | ★★★☆☆ |
| ④ | 点「部署方案」 | **下载并安装软件** | ★★★★★ |

**前三步是纯本地、无副作用的，第四步会真正修改用户的电脑。** 方案里必须把这条界线画清楚。

## 1. 硬件检测

### 实现方式

Tauri 命令 `get_system_info`，一次性读取：

| 字段 | 来源 | 备注 |
|---|---|---|
| CPU 名称 / 核心数 | `sysinfo` | 跨平台，快 |
| 内存总量 / 可用 | `sysinfo` | 字节 → MB |
| 显卡名称 / 显存 | Windows 注册表（`winreg`） | 部分驱动读不到显存 → 返回 `null` |
| 磁盘各分区 | `sysinfo` | 系统盘总容量 / 可用 |
| 操作系统版本 | `sysinfo` | — |

### 交互

```
进入页面 → 自动检测一次（约 200–800ms）
   ├─ 成功 → 四张卡片：处理器 / 内存 / 显卡 / 系统盘
   └─ 失败 → 显示原因 + [重新检测] 按钮

「重新检测」→ 重新执行，按钮进入「检测中…」禁用态
```

### 验收标准

- 显示的 CPU / 内存 / 显卡**与任务管理器一致**
- 浏览器打开时显示「当前环境不支持硬件检测」，不白屏

## 2. 文字 → 软件匹配

这是整个功能的核心，也是最容易做歪的地方。

### 关键决策：用规则库，不用大模型

| 方案 | 准确率 | 离线 | 可解释 | 成本 |
|---|---|---|---|---|
| **规则库匹配** | 高（软件目录有限） | ✅ | ✅ 能说清命中哪个词 | 0 |
| 本地模型分类 | 中 | ✅ | ❌ 黑盒 | 需装模型 |
| 云端 LLM 解析 | 最高 | ❌ | 半黑盒 | 每次调用花钱 |

**v1 用规则库。** 理由：

1. 软件目录是**有限且已知**的（二三十个），不需要通用理解能力
2. 用户描述里的关键词高度集中（"转文字""生图""本地""离线"）
3. **匹配不到就显示"无"——这正是要的行为**，规则库天然能做到；LLM 反而会"编"一个看似合理的答案

### 软件目录（数据，不是代码）

```jsonc
{
  "id": "ollama",
  "name": "Ollama",
  "kind": "runtime",              // runtime | model | tool
  "capabilities": ["local-llm"],  // 能力标签
  "keywords": ["本地模型", "离线", "私有部署", "大模型", "本地运行"],
  "sizeMb": 800,
  "requires": [],                 // 依赖的其他软件 id
  "install": {
    "type": "installer",
    "url": "https://ollama.com/download/OllamaSetup.exe",
    "sha256": "……",
    "silentArgs": ["/S"]
  },
  "verify": { "type": "command", "command": "ollama --version" }
}
```

目录以 JSON 形式**打包在客户端**，更新目录不需要发版（远程下发的风险留到 v2）。

### 匹配算法

```
输入：用户描述文本
1. 归一化（去空格、转小写、全半角统一）
2. 对每个软件：
     score = 命中关键词数 × 2 + 命中能力标签数 × 3
3. 按 score 降序
4. 取 score ≥ 阈值(3) 的前 N 个（N ≤ 3）
5. 一个都没有 → 返回「无匹配」
```

**必须展示「为什么匹配」**，例如：

```
匹配到 Ollama
理由：命中关键词「本地模型」「离线」
```

用户能判断匹配对不对，这比准确率本身更重要。

### 匹配不到时的界面

```
未找到匹配的软件

你的描述：帮我做个能自动批改作文的工具
建议：
· 换个说法试试（如「文本处理」「文档问答」）
· 或从下方目录手动选择软件
```

**不要说"暂不支持"就结束**——要给出下一步动作。

## 3. 生成方案

一个技能可能对应多个软件，多个技能之间会有重叠。

### 方案生成做的事

```
输入：已选技能列表
1. 展开每个技能 → 软件集合
2. 去重（两个技能都要 Ollama，只装一次）
3. 依赖拓扑排序（先装 Ollama，才能拉模型）
4. 汇总体积与预计耗时
5. 冲突检测：
     · 磁盘剩余 < 总体积 → 警告
     · 显存不足 → 警告该技能可能跑不动
     · 已安装同款旧版本 → 提示升级而非安装
6. 输出结构化方案
```

### 输出结构

```
技能部署方案
───────────────────────────────
共 3 个步骤，预计下载 5.3 GB，约 12 分钟

[1] 安装 Ollama          800 MB   ← 本地模型运行环境
[2] 下载 qwen2.5:7b      4.5 GB   ← 知识库问答所需
[3] 配置环境变量             —     ← 让命令行能找到 ollama

⚠ 警告：当前显存 4 GB，低于「本地图片生成」建议的 8 GB
```

**警告必须显眼**，因为用户点完部署才失败，体验最差。

## 5. 技能选择：三层下钻（L1 场景 → L2 技能 → L3 依赖）

### 为什么改

原来的技能选择是「一屏平铺几十张技能卡」，普通用户不知道该选什么，
专业用户又看不到「选了这个技能要装什么软件、要授权哪个网站」。

### 层级

| 层级 | 内容 | 谁看 |
|---|---|---|
| L1 | 3 大类（工作 / 学习 / 生活）× 21 个业务场景 | 普通用户：点场景框即选中，到此为止 |
| L2 | 场景下的细分技能（可勾选去掉不需要的） | 想微调的用户：点场景框上的「修改」进入 |
| L3 | 每项技能依赖的软件 / 模型 / 网站，带就绪状态 | 专业用户：可编辑、删除、导入新依赖 |

### 交互

- 页面内切换视图 + 面包屑 + 「← 返回」，不用弹窗（桌面端最稳）
- L2 取消勾选即从本次范围去掉，卡片上显示「N 项技能 · M 个依赖 · K 项待就绪」
- L3 依赖按类型展示，状态用三色徽标：已就绪 / 待接入 / 需授权
- 支持「导入新依赖」与「恢复默认依赖」
- 选择结果存 localStorage（`kaixin.scenarioScope.v1`），重开应用仍保留

### 数据来源

`业务场景技能依赖层级表.xlsx`（3 大类 / 21 场景 / 89 技能条目 / 148 条依赖），
自建技能在「新增技能」时选择归属大类，直接并入对应分类：
技能要求逐行成为 L2 细分技能，匹配到的软件与网站成为 L3 依赖。

由脚本生成 `src/data/scenarioSkills.ts`。**改数据请改 Excel 后重新生成，不要手改 TS。**

## 4. 软件从哪来：内置、按需、引导

决定一个组件怎么交付，看的不是"大小"，而是**许可证、体积、必需性**三个维度。

### 4.1 三个维度

| 维度 | 决定什么 | 优先级 |
|---|---|---|
| **许可证** | 能不能放进安装包 | ★★★★★ |
| **体积** | 用户愿不愿意下 | ★★★★☆ |
| **必需性** | 是不是人人都会用 | ★★★☆☆ |

### 4.2 三层分发

| 层 | 条件 | 放什么 | 落点 |
|---|---|---|---|
| **内置** | 许可证友好 + < 50 MB + 人人要用 | ffmpeg（LGPL 构建）、解压、基础图像处理 | 安装包内 |
| **按需** | 100 MB – 5 GB | Ollama、模型权重、OCR、Whisper | 首次用到才下载 |
| **引导** | 许可证受限 / 需驱动 / 需提权 | AGPL 软件、需系统服务的组件 | 跳官方页，不代下 |

**三层不是按体积分的，是按"能不能、该不该"分的。**

> **引导层只收两类**：① AGPL / 受限许可的软件；② 需要装驱动或注册系统服务的组件。
> Ollama、ffmpeg、Whisper 都有便携版，**一律走"按需下载 + 解压"，不进引导层**——
> 三种交付方式里只有一种能用于它们，避免出现"文档说引导、实现按下载"的错位。

### 4.3 许可证是第一道闸

| 软件 | 许可证 | 能内置吗 |
|---|---|---|
| Ollama | MIT | ✅ |
| Qwen 模型 | Apache 2.0 | ✅ |
| whisper.cpp | MIT | ✅ |
| PaddleOCR | Apache 2.0 | ✅ |
| ffmpeg | LGPL 核心，多数成品构建为 GPL | ⚠️ 只能用 LGPL 构建 |
| Ultralytics YOLO | **AGPL-3.0** | ❌ 需商业授权 |
| 7-Zip | LGPL + unRAR 限制 | ⚠️ 谨慎 |

> **YOLO 是雷区**：AGPL 下"通过网络提供服务"也算分发。
> 做视频截帧 / 主体检测时优先选 Apache 2.0 的替代品（如 YOLOX），或买商业授权。
>
> 所有许可证以各项目 `LICENSE` 文件为准，商用前建议法务确认。

### 4.4 清单驱动，不硬编码 URL

三种交付方式的量级对比：

| 方案 | 安装包 | 首次可用 | 更新成本 |
|---|---|---|---|
| 全内置 | 5.3 GB | 下载完即可用 | 每次全量重下 |
| 全下载 | 80 MB | 10–40 分钟 | 快，但源挂了就废 |
| **三层** | **80 MB** | 核心功能开箱可用 | 只下增量 |

全下载有两个死穴：

1. **官方 URL 会变** —— 地址写死，对方一换路径，所有旧客户端同时失效
2. **源会挂、会限速** —— 用户不会觉得是网络问题，只会觉得你的软件坏了

所以用**清单**描述，不硬编码：

```jsonc
{
  "id": "ollama",
  "version": "0.5.7",
  "layer": "on-demand",
  "license": "MIT",
  "sources": [
    "https://github.com/ollama/ollama/releases/download/v0.5.7/ollama-windows-amd64.zip",
    "https://mirror.example.com/ollama/0.5.7.zip"
  ],
  "sha256": "……",
  "sizeMb": 820,
  "fallback": "https://ollama.com/download"
}
```

| 字段 | 作用 |
|---|---|
| `sources` 多源 | 官方挂了走镜像 |
| `sha256` | 防篡改、防下载损坏 |
| `version` 版本锁 | 行为可复现 |
| `fallback` | 全挂时引导用户手动下载 |

### 4.5 本项目的分配

| 组件 | 层 | 体积 | 理由 |
|---|---|---|---|
| ffmpeg（LGPL 构建） | **内置** | 30 MB | 抽帧、转视频、旋转，每个技能都要用 |
| 解压 / 压缩 | 内置 | < 1 MB | 用标准库，零依赖 |
| Ollama | 按需 | 820 MB | 不是人人都开本地模型 |
| Qwen 7B | 按需 | 4.5 GB | 开了本地模型才需要 |
| OCR 模型 | 按需 | 15–50 MB | 用到才下 |
| 检测模型（替代 YOLO） | 按需 | 20–100 MB | 选 Apache 2.0 的替代品 |
| 抖音开放平台 | 不下载 | — | 是**授权**，不是软件 |

**安装包控制在 80 MB 左右，开箱即可做视频截帧与图转视频。**

### 4.6 企业离线包

私有化 / 内网环境单独提供「全量离线包」（约 5.5 GB），包含所有层。

**但不作为默认下载项**——它只服务极少数场景。

## 5. 部署执行（优先便携版）

**这是整个功能里唯一会修改用户电脑的动作。**

核心判断：**能解压就别装。** 主流 AI 运行时都提供便携版 zip，解压即用，
比跑安装器更轻、更快、更安全。

| 级别 | 做什么 | 管理员权限 | 用户操作 | 建议 |
|---|---|---|---|---|
| **P（首选）** | 下载 zip → 校验 → **解压到私有目录** | 不需要 | 无 | ✅ **v1 做这个** |
| L1 | 只给命令，用户自己执行 | 可能需要 | 全手动 | 兜底 |
| L2 | 启动第三方安装程序 | 常需要 | 点"下一步" | 无便携版时才用 |
| L3 | 静默跑安装器（`/S`） | 需要 | 无 | ❌ 不建议 |

### 4.1 为什么便携版是更优解

| 维度 | 跑安装器 | 解压便携版 |
|---|---|---|
| 管理员权限 | 常需要 | **不需要** |
| UAC 弹窗 | 要弹一次 | **完全不弹** |
| 杀软误报 | 高（被视为"程序化安装"） | **低**（解压不是执行） |
| 静默可能 | 取决于安装器参数 | **天然静默** |
| 卸载残留 | 注册表 + 目录 | **删目录即可** |
| 多版本并存 | 难 | **容易** |
| 失败定位 | 难（安装器无输出） | 好（少个文件立刻可见） |

**"轻量静默安装"的本质不是把安装器跑得很安静，而是根本不用安装器。**

> 补充说明：**装自己的程序**和**替用户装别人的程序**是两回事。
> 前者（例如本产品的安装包）用 Tauri NSIS 打包，天然支持 `/S` 静默，这没有问题；
> 后者要调用第三方安装器，受对方参数、UAC、杀软启发式规则约束，才是风险所在。

### 4.2 三个组件都有便携版

| 组件 | 便携形态 | 体积 |
|---|---|---|
| Ollama | `ollama-windows-amd64.zip`（官方 release） | 约 700 MB–1 GB |
| ffmpeg | `ffmpeg-*.zip`（gyan.dev / BtbN build） | 30–150 MB |
| whisper.cpp | `whisper-bin-x64.zip` | 约 20 MB + 模型 |

> 体积以发布页为准，代码里从 manifest 读取，不写死。

### 4.3 部署流程（便携版）

```
用户点「部署方案」
   ↓
[1] 弹出确认框：列出每一步 + 来源 URL + 体积
   ↓ 用户勾选「我确认」
[2] 逐个执行：
   ├─ 下载 zip 到 %LOCALAPPDATA%\Kaixin\downloads\
   ├─ 校验 SHA-256（不匹配则中止并删除）
   ├─ 解压到 %LOCALAPPDATA%\Kaixin\runtime\<id>\
   ├─ 写 manifest.json（版本、路径、安装时间）
   └─ 执行 verify 命令确认可用
   ↓
[3] 模型类：执行 ollama pull <model>（CLI，可全自动）
   ↓
[4] 输出结果：成功 / 失败 / 跳过，附日志路径
```

### 4.4 便携版带来的新问题：PATH

`ollama.exe` 不在系统 PATH 里，命令行调不到。三种解法：

| 方案 | 做法 | 评价 |
|---|---|---|
| **绝对路径调用** | 直接用 `runtime\ollama\ollama.exe` | ✅ 推荐，不污染系统 |
| 子进程 PATH | 启动子进程时注入临时 PATH | 备选 |
| 写系统 PATH | 修改用户环境变量 | ❌ 卸载会残留，非必要不做 |

### 4.5 什么时候仍然必须用安装器

- 需要安装驱动的（如某些 GPU 运行时）
- 需要注册系统服务的
- 发布方明确不提供 zip

这三种情况走 L1（给命令）而不是 L2，让用户自己决定。

### 4.6 必须有的安全设计

| 措施 | 说明 |
|---|---|
| **软件白名单** | 只允许安装目录内的软件，不接受任意 URL |
| **哈希校验** | 下载后校验 SHA-256，不匹配立即中止并删除 |
| **执行前展示** | 列出每条命令、来源域名、文件体积 |
| **逐项确认** | 用户可取消其中任意一项 |
| **完整日志** | 写入 `%LOCALAPPDATA%\Kaixin\logs\deploy-*.log` |
| **不自动提权** | 需要管理员权限时，明确告知并让用户手动以管理员运行 |

## 6. 状态机

```
页面级
  idle ──检测──▶ detecting ──成功──▶ ready
                            └─失败──▶ failed ──重试──▶ detecting

技能级
  draft ──点「配置 AI 软件」──▶ matching ──▶ matched
                                         └─▶ unmatched（显示"无"）

方案级
  none ──生成──▶ generated ──部署──▶ deploying ──▶ done
                                              └─▶ failed

单步部署
  pending ▶ downloading ▶ verifying ▶ installing ▶ verifying-install ▶ done
                                              └──────────▶ failed
```

每个状态都要有对应的界面表现，**不能只有"转圈"**。

## 8. 数据模型（本地）

PoC 阶段全部在本机，**不需要后端**。

```ts
interface SoftwareEntry {
  id: string;
  name: string;
  kind: "runtime" | "model" | "tool";
  capabilities: string[];
  keywords: string[];
  sizeMb: number;
  requires: string[];
  install: { type: "installer" | "cli"; url?: string; sha256?: string; command?: string };
  verify: { type: "command"; command: string };
}

interface CustomSkill {
  id: string;
  name: string;
  description: string;
  matchedSoftware: string[];   // 空数组 = 未匹配
  matchReasons: string[];      // 命中哪些关键词，给用户看
  createdAt: number;
}

interface DeployStep {
  order: number;
  softwareId: string;
  action: "install" | "pull-model" | "set-env";
  status: "pending" | "running" | "done" | "failed" | "skipped";
  message?: string;
}
```

存储**统一归属，只有一套持久化引擎**：

| 数据 | 存哪 | 说明 |
|---|---|---|
| 界面临时状态（当前选中、未保存草稿） | 前端内存 / `localStorage` | 可丢，不进备份 |
| 用户数据（自定义技能、笔记、私域文档） | **Go sidecar 的 SQLite**（`%LOCALAPPDATA%\Kaixin\data\app.db`） | 唯一持久化落点 |
| 部署产物与其清单 | `%LOCALAPPDATA%\Kaixin\runtime\<id>\` | 文件形态，不入库 |

**禁止用 `tauri-plugin-store` 另起一套本地存储。** 两套引擎意味着两套备份、两套迁移、两套加密，
重装或升级时必然对不上。详见 `docs/08` 第 11 节。

## 9. 分阶段与验收

| 阶段 | 内容 | 工期 | 验收标准 |
|---|---|---|---|
| **S1** | 硬件检测 | 半天 | 显示值与任务管理器一致；「重新检测」可刷新 |
| **S2** | 软件目录 + 匹配 | 1 天 | 输入「本地离线跑大模型」→ 匹配 Ollama；输入乱码 → 显示"无" |
| **S3** | 方案生成 | 半天 | 选 2 个技能，重叠软件只出现一次；磁盘不足有警告 |
| **S4** | 部署 L2 | 1–2 天 | 下载→校验→启动安装器→验证，全程有日志 |
| **S5** | 静默安装 / 回滚 | 待定 | 需要代码签名后再评估 |

**S1 单独可交付**，做完就能演示。**S4 之前不要碰 S5。**

## 10. 风险登记

| 风险 | 影响 | 应对 |
|---|---|---|
| **许可证违规分发** | ★★★★★ | 内置前逐项核对 LICENSE；AGPL / GPL 只引导不代下 |
| **杀毒软件拦截** | ★★★☆☆ | 优先便携版解压（不是执行安装器）；白名单 + 哈希 + 明确来源 |
| **UAC 提权被拒** | ★★★★☆ | 提前说明需要管理员；提供"以管理员重开"指引 |
| 安装器不支持静默参数 | ★★★★☆ | L2 只启动安装器，不传参数 |
| 下载中断（5 GB 模型） | ★★★☆☆ | 断点续传 + 可暂停；失败可重试 |
| 用户已有旧版本 | ★★★☆☆ | 检测版本，提示升级而非重复安装 |
| 匹配错误（给错软件） | ★★★☆☆ | 展示匹配理由；允许用户手动改选 |
| 卸载残留 | ★★★☆☆ | 提供"查看已安装"列表和卸载指引 |

## 11. 一句话总结

> **前三步（检测 / 匹配 / 方案）是纯本地、可回滚的，风险为零，先做完。**
> **第四步（部署）优先走便携版解压——不要管理员、不弹 UAC、不触发杀软，真正做到"轻量静默"。**
> 只有没有便携版的组件，才退回到「给命令让用户自己执行」。
