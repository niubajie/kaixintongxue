# 红线分级与纠偏

> 版本 v1.0 ｜ 2026-11-19 ｜ 只写「怎么分级、怎么纠」，红线清单见 `AGENTS.md` 第 4 节（单一真相）

## 0. 这份文档解决什么问题

红线本身写在 `AGENTS.md`，但只有清单不够用：

- 同样是越红线，有的必须**立刻停手**，有的可以先记下来排期
- 出了问题要**知道找谁、按什么顺序处理**

这份文档定义分级、检查点、偏差分类与纠偏流程。

## 1. 红线清单（引用，不复制）

七类硬约束见 `AGENTS.md` 第 4 节「安全红线」，要点：

| 编号 | 红线 | 违反后果 |
|---|---|---|
| R1 | 拼接 SQL | 注入，数据可被拖走 |
| R2 | 日志打印手机号/密码/Token/正文 | 个人信息泄露 |
| R3 | 查询不带 `user_id` | 水平越权，看到别人数据 |
| R4 | 密码用 MD5/SHA1 | 撞库即明文 |
| R5 | 密钥写进代码或 Git | 密钥泄露，账单爆炸 |
| R6 | 客户端校验当最终校验 | 绕过前端即可越权 |
| R7 | 私域文档批量导出 | 违背私域承诺 |

## 2. 分级（L0–L3）

| 等级 | 判定 | 响应时限 | 处置 |
|---|---|---|---|
| **L0 致命** | 数据已泄露 / 密钥已进 Git / 越权可复现 | 立刻 | 停手，先止血再修，修完补审计 |
| **L1 严重** | 存在可被利用的绕过路径，但未发生 | 当天 | 当次提交内修复，不允许带入下一版 |
| **L2 一般** | 违反约定但风险可控（如内部接口缺校验） | 本迭代 | 记入差距表，排进当前迭代 |
| **L3 提示** | 风格与一致性问题 | 有空再改 | 记入待办即可 |

判定口诀：**能不能拿到别人的数据**。能 → L0/L1；不能 → L2/L3。

## 3. 四个检查点

| 检查点 | 检查什么 | 落在哪 |
|---|---|---|
| **需求评审** | 是否引入新的数据面（新表、新字段、新对外接口） | `docs/04` 决策记录 |
| **编码** | 是否走现有分层与网关（模型调用只走 modelgw，壳能力只走 platform） | 提交 diff |
| **提交前** | `go vet ./...`、`go test ./...`、`npm run typecheck` 三件套 | 每次提交 |
| **上线/验收** | 权限矩阵回归、审计可查、错误提示不泄露内部信息 | `docs/16` 验收清单 |

## 4. 四维偏差

纠偏不只看「有没有 bug」，还要看这四维是否偏离：

| 维度 | 典型偏差 | 判别信号 |
|---|---|---|
| 范围 | 需求外的功能被顺手做进来 | diff 里出现没人要的模块 |
| 质量 | 只做界面不做数据链路 | 点了按钮没反应、刷新即消失 |
| 成本 | 长上下文全量重发、无用量记录 | token 消耗随对话轮数线性涨 |
| 进度 | 文档写了但代码没做，或反之 | 文档与 `docs/13` 状态不一致 |

**质量维度的判据**：功能是否「可复现」——重开应用、换一台机器，还成立吗。

## 5. 纠偏状态机

```
发现 → 定级 → 止血 → 修复 → 复核 → 归档
```

| 阶段 | 动作 | 产出 |
|---|---|---|
| 发现 | 谁发现谁记录，写清现象与复现步骤 | 一条问题记录 |
| 定级 | 按第 2 节判 L0–L3 | 等级 + 响应时限 |
| 止血 | L0 先行：撤密钥、回滚、关入口 | 风险不再扩大 |
| 修复 | 改代码，同批补一条回归用例（能补则补） | 提交 |
| 复核 | 用原复现步骤再跑一遍，确认不复发 | 复核结论 |
| 归档 | 写入 `docs/13` 差距表或直接关闭 | 关闭记录 |

**不许跳过复核**：改完没验证等于没改。

## 6. 当前执行情况（如实记录）

已经做到的：

| 项 | 落地方式 |
|---|---|
| 提交前三件套 | `go vet` / `go test` / `npm run typecheck` 每次执行 |
| 越权拒绝留痕 | 服务端 `denyWithAudit`，拒绝也写审计 |
| 密钥不外泄 | API Key 只存本地库设置，不下发页面；服务端读环境变量 |
| 权限矩阵 | Owner / Admin / Member 三级，服务端强制（见 `docs/15`） |
| 路径安全 | 本地服务 `pathsafe.go` 校验相对路径，禁止越出根目录 |

还没做的（属于 L3，记着但不紧急）：

- SQL 注入静态扫描（目前靠「禁止拼接 + 参数化」的人工约定）
- 日志脱敏自动检查
- 异常与拒绝事件的告警推送
- 移动端壳的安全存储（`bridge.secureStorage` 已定义，尚未接 Capacitor 实现）

## 7. 红线自查表（每次发版前打勾）

- [ ] 新增查询都带 `user_id`（管理接口除外，且已鉴权）
- [ ] 没有把密钥、Token、手机号写进代码或日志
- [ ] 客户端能绕过的校验，服务端也有
- [ ] 模型调用走 `modelgw`，且写了 `usage_records`
- [ ] 新接口在 `docs/13` 有状态记录
- [ ] 改完重跑了构建与验收清单
